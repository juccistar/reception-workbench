# 现行规则

本文维护当前源码 0.3.3 的产品规则。发行及新目录验证正在进行，具体状态见[本版说明](0.3.3发布说明.md)。原始 Ready 中的 14 字符正文具体内容未知，真实 Accio 两轮发送尚未执行。业务目标见[需求文档](项目开发/01-需求文档.md)。

## 规则的适用顺序

用户当前指令和仍有效的明确授权，决定本次操作范围。产品功能与接口以当前源码、需求和实施契约为准；版本是否通过验收，以对应证据为准。历史报告、旧脚本注释和协作请求中的“本轮”“只执行一次”“不追加调用”，只描述当时任务，不能自动变成永久产品限制，也不产生新的操作授权。

历史测试对象的授权仍只覆盖其明确对象。把“程序支持其他客户接待”和“可以向其他客户发送测试”混为一谈是不正确的；本次整理不扩大测试客户、AI调查或外部写入范围。

## 当前行为

| 历史描述或容易产生的误解 | 现行行为 | 处置 |
| --- | --- | --- |
| 图片只能保存元信息，不能预览或参与接待 | 已支持受控取图、安全预览和独立视觉，观察与确认事实分开 | 旧能力说明限定到原版本，不能继续当当前限制 |
| 人工回复也必须先完成AI、采购信息或最后一条买家消息检查 | 普通人工正文有独立路径，无上述前置；保留身份、版本、幂等和整会话未决保护 | 当前说明统一；旧人工模式仅保留接口兼容语义 |
| 必须先对某条AI草稿预演，才能打开全局自动接待 | 全局开启不以某条旧草稿的预演为前置；实际每条自动发送仍做原生预检 | 区分诊断按钮与实际发送保护 |
| 只能接待某个测试客户，或必须配置AI/发送次数上限 | 程序支持选定客户、开启时已同步客户、授权后新消息三类范围；0.2.22在当前授权内不限AI/发送次数、保留统计 | 用户仍明确选择本轮范围；次数不限不恢复重启或人工接管后的权限，测试发送仍只覆盖明确授权对象 |
| 没有飞书就不能接待 | 本地消息、需求和待报价独立可用，飞书异步且可选 | 不再把飞书配置当本地接待前置 |
| 数据目录只能固定在系统盘 | 设置页可选择本机目录、迁移、备份和恢复 | 使用当前实际目录；不能假定默认根就是业务根 |
| 当前窗口已经通过AI检查或正在自动接待 | 检查、范围和开关具有时点及进程边界，历史截图不代表此刻状态 | 实时看窗口；重启不恢复旧自动权限 |

## 0.2.22连续接待语义

0.2.22按用户确认的六项方案实施：质量提醒与正文硬错误分开、事实逐项核验、人工协助与接管分开、待报价续聊、不限次数、生成自动修复/退避重试及核实结果实际跟进。第4项没有新增持续模式、重启授权恢复或设置不断权。可用正文不会因商业承诺/数字缺依据而转人工，提示词仍追求准确自然，不写允许错误承诺。

协助结果区分内部和可供回复客户，按版本及幂等保存；仅后者可安排对客跟进。unknown只核查原操作，不能通过简短确认、跟进或新事项绕过。业务操作见[连续接待说明](自动接待连续性.md)。

## 0.3.1接待、翻译与失败重试

主动建议是独立路径：身份和AI能力可用时，允许暂停、人工接管、卖家最后发言、无事项或缺项。会话业务补充仅供主动建议引用；生成、查看和翻译不接管、不改正文，采用整段替换并沿人工编辑路径接管。译文和中文展示不改原始事实或来源，不增加语言检测门槛。

正常AI/发送总量仍不限。单条自动失败链按商家、会话、原始消息和回复阶段最多3次总尝试（首次加2次），仅明确未提交的临时错误按5秒、15秒退避；永久或未分类拒绝停止本条。新job、draft或重启不重置计数，unknown只核查原操作，不能以缺失提交标记当作明确未提交。保留旧操作、原错误与回执；失败不自动接管或停止其他客户。

## 当前产品参数与未完成能力

- 默认5秒活动检测、正文排队/读取最多4个、历史/维护补读全账号每60秒一个，均仍为实际调度行为。5秒不是回复时延承诺。
- 一次生成最多处理最近20条中的4张买家照片；原图为受控PNG/JPEG/WebP静态图，当前上限6 MiB。可以另立需求调整，不能因清理文档就宣称这些参数已取消。
- 0.2.20支持不同已核验商家分别使用独立窗口和profile；同商家跨目录全局排他，真实双Accio并行接待闭环仍待验收。统一多账号控制台、找货、RFQ、报价核算未开放；采购事实人工复核和完整交接状态继续按任务台账建设。
- 同版本连续新入站、整班运行及其他未完成验收仍需分别留证。

## 文件与工具边界

业务数据、完整备份和发送证据须按实际配置的位置保护，不能把工作区当作可清理的构建缓存。规则变化应同步需求、代码与验收；文档整理不扩大授权或迁移业务数据。
