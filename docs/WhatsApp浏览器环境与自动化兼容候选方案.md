# WhatsApp内嵌浏览器环境与兼容候选方案

日期：2026-11-14。面向开发与验收人员。

状态：用户已选择继续Electron内嵌路线。本文件保留环境核对与扩展候选的技术边界，具体交付范围以[0.3.18开发方案](0.3.18快速开发方案.md)为准。正式兼容项已进入实施与验证，未引入实验插件或修改正式登录环境；公共页与SDK引导的实际结果见[验证记录](verification/0.3.18.json)。适用范围为当前商家自有账号的客户入站单聊接待。

本版正式工作包括规范客户端标识、校正单视图CDP版本、检查页面加载结果，以及建立同页SDK兼容基线。自动化特征相关处理仍逐项评估，未经验证的处理不进入默认配置。whatsapp-web.js仍为非官方接入，兼容测试不能证明账号不会受限。

## 1. 建立真实环境基线

当前架构为Electron WebContentsView与SDK共用可见页面。正式程序使用中文应用名时，默认User-Agent含中文产品标识，已复现HTTP 400；替换为ASCII产品名后返回200。

通过临时空会话核对真实Electron/Chromium版本、网络与页面标识、Client Hints、平台、语言、时区、窗口与DPR。记录定位所需的版本、布尔检查和受限差异摘要，不采集客户内容、Cookie、Token、二维码或完整指纹原始值。

每项候选改动单独对照基线，记录所解决的兼容问题、SDK回归及回退方式。

## 2. 客户端标识与CDP：本版正式修复

- 保留中文窗口与应用显示名称，WhatsApp请求仅将中文产品标识替换为ASCII产品标识和实际应用版本。
- Chrome/Electron版本从运行环境取得，不写死其他版本；保留原生Client Hints，不凭空补造。
- 保持SDK的`userAgent: false`，避免默认旧Mac/Chrome 101标识覆盖实际环境。
- 校正ViewTransport的`Browser.getVersion`，使用当前WebContents原生CDP版本信息；继续只操作这一个受控页面。
- 核对可见DOM、预注入脚本、回调绑定和SDK使用同一页面、同一会话。
- 明确HTTP错误、网络错误、导航/引导超时与扫码等待。错误文档不继续SDK初始化，旧连接结果不覆盖新连接。

这些修复仅限WhatsApp宿主，renderer不获得任意请求头、脚本、Cookie或CDP接口。

## 3. 自动化环境审计与可选实验

本轮在受控页面审计SDK预注入、必要浏览器API、权限查询，以及`navigator.webdriver`、`window.chrome`、插件/MIME等环境差异。审计结果用于判断兼容性，不能由某个属性值推导平台是否会限制账号。

若发现明确兼容问题，再评估单项处理：

1. 只有可复现地改善该问题、同页SDK及发送回归通过的处理，才可形成默认关闭的宿主实验项。
2. `puppeteer-extra`及`puppeteer-extra-plugin-stealth`仍只是未选定依赖，不预设本版安装、适配或交付整套插件。没有合格候选时可以不新增实验运行配置。
3. 自定义单视图CDP必须验证处理钩子确实作用于可见页面；不能照搬独立Chrome的launch配置。
4. 不破坏SDK对象、回调或事件，不向远程页面暴露工作台业务桥，不影响其他商家会话。
5. 一项处理失败即回退该项。遇到认证、访问拒绝或账号限制停止尝试，不继续换身份或参数试探。

验收只表述为受控环境及SDK兼容测试结果，不声称平台无法识别自动化。

## 4. 环境一致性

优先保留实际平台、语言、时区、屏幕/窗口、DPR及图形媒体能力。使用稳定会话配置，不叠加互相冲突的模板。

本版保留Canvas、WebGL、Audio原生输出，不以每次启动随机改值或硬件伪造作为正式功能。未经验证的实验不作为请求头修复或正常接待的依赖。

## 5. 会话与网络

- 继续使用商家隔离的Electron persist partition，不引入第二浏览器或LocalAuth，不迁移登录目录。
- 同一目录保持单个写入者；普通断开和退出保留登录资料，不通过清空Cookie、反复扫码恢复普通连接错误。
- 沿用用户配置的网络；必要时核对页面、静态资源及WebSocket连接，诊断仅保存受限结果。
- 断线、账号变化或明确执行异常撤销自动发送授权，重连不自动恢复；429遵循服务端等待信息。
- 登录资料、完整指纹及完整请求头不进入普通日志、业务导出或发行物。

## 6. 真实Chrome路线的状态

用户已选定本版继续内嵌，真实Chrome不纳入0.3.18实施范围。[路线比较](WhatsApp真实Chrome与内嵌路线评估.md)作为后续参考保留，不要求为本版开发独立Chrome宿主、分发浏览器或重新扫码。

## 7. 接待与故障保护

继续执行入站单聊触发、同客户发送互斥、确切账号/连接代次/目标/正文冻结、原操作防重和确切回执核查。原生页面或手机人工回复接管对应客户。

发送节奏由实际入站、消息合并、队列及平台限制决定。unknown沿原操作核查，不因重连、实验开关或新job重发，不以假交互或任意每日次数承诺账号安全。

后台保活、独立健康检查、受限诊断及删除图片覆盖提示仍按0.3.18主方案交付。

## 8. 验证顺序与记录

验证顺序：本地受控页面 → 临时会话公共登录页 → SDK同DOM/同会话证明 → 最终EXE与固定SDK归档。真实账号功能测试另按明确对象和范围执行。

每项结果单独记录，不以公共扫码页通过替代真实登录、收发或平台受理。仅运行影响范围内的定向测试。扩展处理没有满足兼容条件时记录为未采用，正式修复照常交付。
