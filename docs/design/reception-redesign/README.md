# 接待工作台 · 全套前端设计稿

面向日常接待、报价与找货业务人员，以及产品评审。设计覆盖接待页、其他工作台页面、账号启动台、共享模型与 WhatsApp 客户侧栏，使用合成客户、商品、账号、需求和任务，不连接真实业务。WhatsApp 继续使用原始网页及原生客户侧栏，不新增聊天客户端。

直接用浏览器打开 [全套页面设计稿](pages.html#home)，或 [客户接待页](index.html)。页面间导航已相互连接，所有资源位于本目录，无需安装依赖或联网。顶部浅色工具条只用于设计预览，不属于正式软件。

2026-11-16 追加要求已纳入：取消发送记录弹窗及所有入口；客户列表、聊天顶部、档案与关联选择均不显示头像或字母头像占位；产品库采用与采购中心一致的紧凑清单，每行仅保留小缩略图，不采用大图卡片。聊天显示当前进度、失败和发送待确认状态；不提供额外手动核查操作，底层防重与原操作记录保全。

## 设计方向

让接待员围绕一个客户完成阅读、理解需求和回复。使用雾白工作区、钴蓝操作色与深蓝导航，以一处清晰的色彩建立方位；客户列表、聊天、需求资料依靠宽度与留白区分，避免层层嵌套卡片。

| 色彩 | 值 | 用途 |
| --- | --- | --- |
| 雾白 | `#F4F6FA` | 页面底色与次要区域 |
| 纯白 | `#FFFFFF` | 聊天、内容表面 |
| 墨蓝 | `#1D2B42` | 文字与导航 |
| 钴蓝 | `#3458DB` | 当前客户、主操作与交互焦点 |
| 松绿 | `#2A7D69` | 已连接、已保存、已受理 |
| 琥珀 | `#A36A20` | 待核查与人工状态 |

中文使用 Windows 微软雅黑 UI，配合 Segoe UI 的拉丁字母；标题 18–21 px、主要正文 14 px、辅助内容 11–12 px。聊天以自然英文原文为主，中文译文降低对比但保持可读。

```text
┌─────────┬───────────────────────────────────────────────────────────┐
│         │ 商家 / 客户接待                         接待状态与启停    │
│  导航   ├─────────────┬───────────────────────────┬─────────────────┤
│         │ 找客户      │ 当前客户 / 接待方式         │ 客户资料        │
│  接待   │ 搜索、筛选  │ 客户摘要                    │ 当前需求 / 图片 │
│  商品   │             │                            │ 规格、数量、交期│
│  供应商 │ 客户列表    │ 原文聊天与按需译文          │ 更多需求字段    │
│  资料   │             │                            ├─────────────────┤
│         │             │ 自动回复进度（独立）        │ 业务补充        │
│  设置   │             │ 建议 / 普通单正文 / 发送    │ 附件、自动保存  │
└─────────┴─────────────┴───────────────────────────┴─────────────────┘
```

文字默认左对齐，消息根据发送方分列；主要动作在右下方形成稳定操作位置。右侧资料可收起，窄窗口改为抽屉。

## 设计自检与取舍

最初考虑在页顶增加接待数量、响应速度和完成率，但这些统计会挤压实际聊天，所以删除。蓝色集中用于选中客户与发送动作，正常需求字段使用简单清单，不把每个字段装进独立卡片。使用商品图提供真实业务语境，不加入装饰性插图、营销标题或大面积渐变。

当前客户采用人工接待；全局自动接待仍可保持开启，二者分别显示。自动回复有独立进度区域，建议则出现在人工输入框上方。业务补充固定在需求资料下部，内容编辑后自动保存。需求只读，查看旧事项不改变当前接待事项。

## 可体验的交互

- 搜索客户、切换列表筛选、切换客户，人工草稿与业务补充按客户分别保留。
- 收起与展开客户资料；窄窗口打开客户列表与资料抽屉。
- 开关中文译文、查看完整摘要、查看商品原图。
- 回复建议与润色结果均显示外语正文及中文译文；替换只采用外语正文，可重新生成或弃用。
- 人工接管、恢复自动接待点击即执行；点击需求字段旁“来源”直接定位聊天消息。
- 自动接待直接开启，建议直接生成，不做 AI 预检。实际执行失败后才弹出“AI 不可用”，保留输入并可重试；平台连接页的独立检查不作为前置条件。
- 新增的“自动接待范围”下拉框仅放在设置中，有“全部客户”“选中客户”两项；选择后者立即展开可搜索的多选名单。它配置自动接待范围，左侧客户列表仍负责切换当前聊天。
- 聊天顶部常显“补全历史”，同步状态只作用于当前客户；人工接管与恢复也仅影响当前客户。
- 拖动资料栏左边缘调整宽度，拖动采购需求与业务补充间的手柄调整补充高度；支持方向键、双击还原。
- 待我报价的事项列表与详情分别滚动，切换事项保留位置；同客户多个事项共用会话业务补充。
- 补充编辑自动保存，附件选择、粘贴和拖入；附件仅留在当前页面内存。
- 发送本地预览消息；输入中的新正文与已冻结的发送正文分别处理。
- 预览工具条可切换人工、自动及发送待确认状态。未确认时不增加手动核查入口或弹窗，原操作继续保全，不提供重发。
- 译文、图片及历史补全提示只显示必要状态，省去重复的流程解释。设置中保存的自动接待范围随页面切换保留。

查看和生成建议不会接管客户；手写、替换与人工发送会接管当前客户。恢复客户不等于开启全局授权。普通人工发送不以已有需求或 AI 检查为前置条件。

## 交付范围

这是独立的前端视觉及交互提案，未接入 Electron 桥、Python 业务或真实平台。样例商品图为本地绘制 SVG。正式程序仍需在设计确认后单独实施，并继续保留授权、来源核对、发送保护及已有账本。

本轮不构建软件版本，不运行全量测试。样例图库使用同一份合成 SVG 的不同裁切展示五张缩略图，正式实现应使用各自独立的真实原图。

## 实际核对

在独立的 Electron / Chromium 预览窗口中检查了 1600、1440、1024 和 390 像素画布。本轮生成接待页 17 张、全套页面 40 张、反馈场景 36 张截图，三组检查均通过；实际查看了主要页面、新增范围选择、43 项报价长列表、拖动布局、历史补全和关键桌面/移动异常画面。已核对导航一致、抽屉位置、无横向溢出、客户草稿与补充隔离、无需求时普通人工发送、旧回执不清新输入、建议不接管客户及 unknown 保全原操作且无手动核查入口。直接开启且无 AI 预检、实际生成失败才弹窗、失败后可重试且保留正文/补充、独立模型检查不改变启停，以及双语建议/润色、直接接管/恢复、来源直接定位、范围跨页保留、单行状态、历史按客户隔离、拖动/方向键/双击复位、报价分区滚动与位置保留均通过。没有访问真实业务数据或发出外部网络请求。

首轮隐藏窗口截图曾超时，改为可见的隔离预览窗口后通过；首轮看图发现的窄窗口抽屉定位和消息滚动问题均已修正并重新截图。

可复现脚本为 [接待页检查](render-preview.mjs)、[页面检查](render-suite.mjs) 与 [反馈场景检查](render-feedback.mjs)，结果见 [接待页报告](preview-verification.json)、[全套页面报告](suite-verification.json) 和 [反馈报告](feedback-verification.json)。新增拖动检查首轮因小数像素断言失败，修正断言并复测通过，过程保留在 preview-attempt-03.json。这些检查只覆盖设计原型，不替代正式软件验收。
