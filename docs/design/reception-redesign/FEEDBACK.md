# 接待页状态与弹窗方案

面向接待人员与产品评审。打开 [场景目录](feedback.html) 查看实际画面。此目录使用合成客户、正文、回执和错误，目录工具不进入正式接待流程。

常规操作直接执行，状态只写一行。人工接管、恢复自动接待、发送结果待确认和需求来源不经过确认弹窗；仅实际 AI 调用失败、查看图片，以及退出时有未保存内容等场景使用弹窗。自动接待沿用设置中已选范围，不在启动提示里宣称接待全部客户，也不做 AI 预检。

| 场景 | 位置与表现 | 动作 |
| --- | --- | --- |
| 整段回复建议 | 输入框上方，外语正文及中文译文 | 替换正文、重新生成、弃用 |
| 润色结果 | 同一结果区，润色正文及中文译文 | 替换正文、重新生成、弃用 |
| 建议生成中 | 一行“正在生成建议” | 取消生成 |
| 建议已失效 | 一行状态 | 重新生成、弃用 |
| 人工接管 | 当前客户立即切换为人工状态 | 点击即执行 |
| 恢复自动接待 | 当前客户立即解除人工接待 | 点击即执行，实际接待仍受全局开关及所选范围约束 |
| 开启自动接待 | 顶部立即显示接待状态 | 按设置中的范围开启 |
| 退出时有未保存内容 | 确认弹窗 | 继续编辑、保存并退出 |
| 发送明确未提交 | 一行“发送未提交” | 仅重试确切未提交的原正文 |
| 请求尚未确认 | 一行状态 | 无额外手动核查动作 |
| 发送结果待确认 | 一行状态，保留输入 | 无核查按钮、无核查弹窗、无重发 |
| 连接断开 | 一行状态 | 重新连接 |
| AI 调用失败 | 执行失败后弹出“AI 不可用”及短因 | 关闭、查看模型设置 |
| 译文暂不可用 | 原译文位置只显示状态 | 无解释行 |
| 业务补充保存失败 | 补充区就地显示状态 | 重试保存 |
| 回复正文保存失败 | 输入区就地显示状态 | 重试保存 |
| 附件读取失败 | 附件区一行状态 | 重新选择 |
| 图片加载失败 | 原图位置只显示状态 | 无“需求内容不受影响”等解释 |
| 商品原图 | 图片预览弹窗 | 关闭、复制图片 |
| 需求来源 | 直接滚动到对应消息并高亮 | 点击字段旁“来源”即定位，窄窗口同时关闭资料抽屉 |
| 保存成功 | 短暂轻提示 | 自动消失 |
| 历史补全中 | 按钮忙碌状态及一行“正在补全历史” | 无流程解释 |
| 历史补全失败 | 一行状态 | 使用聊天顶部补全按钮重试 |

建议和润色的中文译文只供阅读，替换或发送只采用外语正文。设计原型为已知合成样例提供对应译文，任意新输入无真实翻译结果时只显示“译文暂不可用”，不编造译文。

去掉核查入口不改变发送结果本身：未确认的原操作继续保全，后台沿原操作处理；不把未知结果推断成失败、受理或允许重发。接管与恢复也不清除未决发送。切换客户后不显示上一位客户的局部提示或迟到失败。

检查结果见 [feedback-verification.json](feedback-verification.json)，截图位于 [previews/feedback/](previews/feedback/)。隔离检查脚本为 [render-feedback.mjs](render-feedback.mjs)，只覆盖此设计原型。
