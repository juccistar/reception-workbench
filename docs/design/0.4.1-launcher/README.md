# 0.4.1 启动台 UI 设计稿

面向工作台使用者及产品评审。本目录保留需求评审阶段的独立交互稿，所有账号、联系人和操作结果均为合成预览。正式实现已另行进入开发和窗口验证，实际状态见开发方案与验证记录，不以本目录的合成截图替代。

打开[启动台交互稿](index.html)或[聊天客户侧栏交互稿](chat-sidebar.html)，可筛选分类、编辑账号、复制完整授权口令、调整客户关联、体验多账号独立连接和异常状态。底部“预览状态”工具条属于设计稿，不进入正式软件。追加需求与正式接入路线见[更新开发方案](../../0.4.1开发方案.md)。

## 首页

首页使用“全部 / 国际站 / WhatsApp”三个分类，同一列表呈现两种账号。每张卡片显示名称、渠道、账号尾号和当前状态，右侧紧邻状态放置常显的铅笔编辑按钮，以及该账号的主操作。

| 当前状态 | 主操作 |
| --- | --- |
| 国际站窗口已打开 | 打开窗口 |
| 国际站需要授权 | 授权 |
| WhatsApp 未连接或连接失败 | 连接 |
| WhatsApp 已连接或等待扫码 | 打开窗口 |

“自动接待中”作为独立的次要状态显示，连接成功不代表自动接待已开启。账号卡片各自可操作，无需先选中某一行。首页不展示使用教程、环境选择器、连接参数或维护表单。

右上角保留“添加账号”和全局“设置”。添加时选择“国际站”或“WhatsApp”；添加 WhatsApp 只填写账号名称并点击“连接”。扫码要求在此时出现。模型配置留在全局设置，首页底部仅保留简洁的就绪状态和设置入口。

国际站添加、授权和重新授权均提供“复制口令”。复制全文包含开头说明、完整Start-Process命令、空行和结尾说明；正式实现调用宿主的copyAuthorization复制info.instructions，不截取命令行。设计稿用占位安装路径演示全文复制，正式路径由当前安装位置生成。

## 每个账号的设置

编辑按钮打开右侧设置面板；窄窗口使用占满窗口的面板，保存按钮固定在底部。

**WhatsApp**：账号名称、自动接待、接待商家、新联系人的默认商家，以及联系人分配入口。接待商家和默认分配在开启自动接待后展开。商家使用短名称选择，不铺开常驻复选框。接待模型显示当前状态，点击进入共享设置。

**国际站**：显示名称、已核验公司、接待设置及共享模型入口。显示名称属于本地备注，不覆盖已核验的公司身份；接待规则和业务资料仍在对应账号窗口管理。

**联系人分配**：独立列表，支持搜索。选择联系人后设置商家及是否自动接待，不要求用户手填联系人 ID 或国际站会话 ID。变更商家后明确提示该联系人接待将暂停。

连接详情、备份恢复和已有历史接入记录放入“更多设置”。正常账号没有历史待办时，不展示旧接入入口。尚未开放的回写功能不展示。

## 提示出现的时机

| 触发 | 呈现方式 |
| --- | --- |
| 首次连接、需要重新登录 | “等待扫码”，提示“请在新窗口完成扫码”，提供“打开窗口” |
| 连接另一个 WhatsApp 账号 | 直接为该账号连接，保留其他账号的连接与接待状态，不显示切换确认 |
| 连接失败 | 在卡片右侧原状态位置显示简短原因，如“连接超时”；悬停可查看提示，操作使用“连接”。不另加提示条，卡片高度和其他状态一致 |
| 开启接待缺少模型、商家或历史确认 | 在操作位置显示缺项和可直接继续的入口 |
| 开启或扩大自动接待范围 | 确认本次账号和商家范围；正式实现沿用原生确认 |
| 更改默认商家 | 编辑时提示仅影响新联系人 |
| 更改联系人商家 | 保存后暂停该联系人的接待；待发送操作仍归原商家 |
| 发送结果未知 | 卡片右侧状态区域附待核查数量，进入“发送核查”查看原结果；不是每条消息都要人工确认，正常状态不显示，且不提供重发 |

普通打开窗口、修改名称和筛选账号不增加确认弹窗。页面按钮统一使用“连接”“打开窗口”“断开连接”，不带浏览器名称。

## 聊天客户侧栏

可收起面板跟随当前单聊显示客户信息、接待商家、国际站客户、摘要与需求，并提供“关联客户”和“人工接管 / 恢复接待”。正式关联使用当前商家已保存的客户名称或买家标识搜索，不显示会话ID；没有可信公司字段时不提供公司搜索。商家变更须保存并暂停该客户接待，切换聊天不能把旧资料或未保存关联带给新客户。

图中的聊天界面只是位置示意，不新增聊天客户端。正式实现已采用Chrome原生侧栏扩展，通过自有私有pipe安装固定资源，并在隔离Chrome中验证宿主通路、客户关联及迟到请求拒绝；真实已登录账号的当前客户识别尚未验收。用户可决定原生侧栏位置，不能保证程序强制固定右侧。当前HTML仍为独立合成预览，未接入真实Chrome、SDK或业务数据。
