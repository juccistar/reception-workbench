# 0.3.21：真人聊天式自动分条与普通人工输入

日期：2026-11-15。最终A候选已正式公开发布，源码构建4770407、候选构建307018f均完成后立即本地提交。[下载0.3.21](https://github.com/juccistar/reception-workbench-releases/releases/tag/v0.3.21)。

## 使用变化

- 自动接待按真人即时聊天的口吻和节奏组织一至三条回复，长短随语境变化，不以压成一条为目标，也不固定条数、顺序模板或每条一句。整轮正文预算仍为1200字符。
- 同一轮回复一次生成、按顺序逐条发送，取得确切受理回执后推进下一条；不需要人工编辑或手动接续。沿用0.3.20同步等待、自身回显归属及原发送防重。
- 人工回复恢复普通单输入框，建议只生成一份正文，润色处理整份正文，支持Ctrl+Enter。移除人工分条编辑、合并、当前条目润色与自动尾部提取；旧多项人工建议不兼容、不拼接转换。
- 当前自动进度在聊天区域展示，历史批次放入折叠发送记录，标明类型、时间和逐条结果；已完成提示短暂显示，旧记录不再混在人工输入框内。
- WhatsApp保留原生网页人工聊天，自动批次在工作台状态区展示。确认新建登录环境采用短分区名，原零代及已保存旧代次保持原目录。

## 发送与数据保护

自动回复继续检查身份、授权范围、会话、来源及有效业务依据。已受理条目不重发，unknown只核查原operation；明确未提交的暂时错误沿原次数预算处理，不以新任务或新批次重置。客户新消息、接管、暂停、撤权及真实依据变化停止未提交尾部。

人工发送仍不要求AI检查、已有需求、字段齐全或最后一条来自买家；回执不能清掉发送期间的新输入。旧在途、unknown、部分受理记录和原账本保全，改为单输入框不解除发送围栏。

WhatsApp短分区仅在用户原生确认后新建，不复制或删除旧登录资料，业务库与JSONL账本位置不变。新确认写入的v2登录配置不被旧0.3.20识别，不支持旧程序覆盖或静默回退；未执行新确认时原配置保持不变。深层自定义目录仍须按实际路径验证。

中文需求、独立摘要、多事项归属、业务补充及图片来源、商品链接与供货事实规则继续保留。商品ID提示词段落不增加新判断提醒。
