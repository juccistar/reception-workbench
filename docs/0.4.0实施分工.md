## 2. 全局模型配置共同契约

公共设置快照 `ModelSettingsSnapshot`：

```typescript
{
  format: 'model-settings-v1',
  directory_revision: number,
  profiles: Array<{
    profile_id: string,
    name: string,
    protocol: 'chat-completions' | 'anthropic',
    base_url: string,
    model: string,
    credential_ref: string | null,
    has_key: boolean,
    config_revision: number,
    credential_revision: number,
    capability_revision: number,
    capabilities: Record<string, {status: 'not_checked' | 'passed' | 'failed', checked_at: number | null}>
  }>,
  routes: {
    reception: {profile_id: string | null, route_revision: number},
    translation: {profile_id: string | null, route_revision: number}
  }
}
```

能力键固定 text、structure、single_image、multi_image、combined、translation。能力记录须绑定被检查的配置/凭据修订；检查提交时若已经变更则丢弃。共享范围为同机同 Windows 用户的全部商家，无商家覆盖；授权和业务内容仍按商家/实际数据根隔离。

保存请求使用 `expected_directory_revision`、完整 profiles 编辑列表、两个 routes 选择及按 profile_id 的 `credential_changes`；密钥动作明确 `keep | replace | clear`。跨进程锁内比较修订，公开元数据与 DPAPI 密封密钥协调原子提交。仅名称变化不增执行修订。删除仍被引用配置必须同时解除或替换对应路由，不能选第一条回退。

宿主磁盘权威文件 `settings.json` 使用上述公共字段，并额外保存 `encrypted_keys` 字典；其中只有 DPAPI 密文。Python 只读取此文件的元数据/修订，不能解密它。宿主 IPC 返回公共快照时必须去掉 encrypted_keys。大小与条数有界（初始最多 32 个 profile，权威文件最多 1 MiB）；损坏和无法确认当前修订时失败关闭。

宿主通过私有 `_configure_models` 注入：

```typescript
{
  format: 'model-runtime-v1',
  authority_file: string,
  settings: ModelSettingsSnapshot,
  credentials: Record<string, string> // 仅当前两个用途选中 profile_id 的明文 Key
}
```

authority_file 来自宿主真实 KnownFolder，不来自 renderer 路径输入。测试可使用隔离临时权威文件。新请求、结果应用和未提交自动批次推进核对权威文件里实际依赖的用途/profile 修订，不因目录改名/无关 profile 变化取消任务。更新私有配置时计算受影响用途，接待撤销相应商家自动授权，翻译独立更新不撤接待；缺失更新通知也不能继续使用过时配置。已进入平台提交的操作保全原回执与 unknown。

宿主配置模块位于 shared/model-settings.ts、main/model-settings-store.ts 和 main/model-config-host.ts。导出工厂/方法以相应源文件为准；这些文件由配置组提供，其他组读取后使用。独立检查由 Python `--model-check` 入口处理，stdin 一条受限 JSON，stdout 一个受限最终结果，不构造 ReceptionService。配置组提供宿主检查进程和同 profile/修订的去重/取消；后端组接 CLI 分派；provider 组实现检查逻辑。首次页面打开或保存不调用模型。

## 3. Python 模型接口共同约定

provider 组提供 model_router.py 中的 ModelRouter：configure(packet)、resolve(purpose, required_capabilities)、assert_current(snapshot)、close()，以及明确的错误分类和私有凭据生命周期。configure 返回受影响的用途集合；resolve 返回仅含用途/profile/执行修订的不可变快照（不得含 Key）。assert_current 每次核对权威文件实际依赖修订；被撤销、过时、损坏或无法读取均明确失败。具体方法签名和结果结构由 provider 组在上述 notes 文档中及时给出。

LiveIntegration 保留身份/读取/发送/真实采购职责；接待生成通过注入的 ModelRouter/模型生成模块执行，不隐式调用 Accio AI 回退。provider 组负责此分层与图文编码、图片清单证据和共用输出校验接口。后端组负责给当前 facade 注入 router，并将所有生成、应用、能力门控及批次推进接到冻结修订。仅添加模块而未接入调用链不算完成。

正常接待同轮文字+必要原图，返回当前 reply_messages、需求增量和摘要；普通润色只改冻结正文，翻译使用受限文字输入。沿用当前业务 schema，模型不持有身份令牌或任意工具。模型尝试链和平台发送重试完全分开；SDK 隐式重试为零，默认模型最多两次且上传后无结果不自动重放。按方案保留单生成、单翻译及进程总量上限；不为完成配置共享强制增加跨进程模型网关。

## 5. 完成标准

模块开发报告必须列实际修改文件、测试命令和真实结果、跨组待接线项以及未实现范围。测试失败不能写成通过；缺依赖的交叉验证延后到整合阶段。不得用 TODO、仅配置 DTO 或假成功替代实际调用链。

默认只交付 live 正式业务，默认桌面入口为启动台；生产参数不能开启合成工作区。测试可保留隔离夹具，发行闭包不包含合成 provider/种子。旧 demo 目录、mode/namespace、业务记录、accepted/unknown 不删除或改写。
