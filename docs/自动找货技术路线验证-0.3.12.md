# 自动找货技术路线验证

日期：2026-11-13。面向后续采购功能设计及验收。本次只验证技术入口，0.3.12没有加入找货、供应商绑定、询价、报价核算或自动报价发送。

## 已得到的结论

**可以通过飞书把合成找货任务交给当前Accio Agent，由已启用的采购插件执行原生只读搜索并返回候选。直接由工作台调用的正式外部搜索API尚未验证。**

现阶段适合把飞书用作异步技术任务通道，Accio原生采购工具承担找货，工作台保存任务及核验后的候选。第三方大模型不是必需环节；接待继续使用Accio，报价金额和适用条件以后应由程序依据明确规则计算。供应商联系、询价、报价采纳及客户发送必须分别建立授权、证据和未决结果处理，不能仅凭聊天机器人回复“完成”推进。

## 本次实际验证

| 入口 | 实测与边界 |
| --- | --- |
| workctl v0.1.65 `icbu tm get-product` | 对用户提供的公开商品ID1601904072453只查一次，传入当前成员身份`--self-ali-id`。约1,840ms成功，返回data字符串中的prod_info多行文本；没有URL、主图或SKU图，记录no_link，不拼接URL。 |

| 已启用`accio-com-buyer-assistant` 0.20.6的`product_supplier_search` | 飞书技术任务触发一次Agent原生只读搜索，查询plain cotton tote bag，币种USD、目的地US。返回声称200条Alibaba.com结果，报告只保留前三条公开候选。没有供应商联系、询价、RFQ、发布采购需求、下单或付款。 |

当前商家核对只获得成员aliId 2500002602126，self=true、admin=false；主账号对应关系没有返回，不据此推断商品归属。未自动启用1688插件或修改权限。

有一次data-advisor帮助命令被宿主守卫拒绝，已记录并停止，没有换身份或渠道绕过。其余成功证据不抵消这次拒绝，也不证明该被拒入口可用。

## 搜索返回的现实限制

本次原生工具返回Markdown表格和rendererPayload，而非已验收的外部结构化API。没有taskId、batch_id或requestKey，也没有可信耗时字段；报告明确留空。飞书消息编号只能关联本地发出的任务，不能替代采购工具自己的执行编号或供应商询价回执。

工具schema没有数量/MOQ过滤参数。合成意图是100件，前三条仍出现MOQ200、10和100；程序后续必须检查数量、MOQ、币种、计价单位和有效期，不能直接将第一条当成满足需求或拿页面价格报价。标题、供应商名、认证徽标和供货承诺均未与供应商核实。

本次只证明一次受控只读搜索的通路，未验证失败恢复、长期可靠性、性能、询价入口或供应商回复回收。

## 推荐后续实现顺序

1. **建立持久采购任务。** 以商家、商品档案、需求版本和动作组成任务关联，保存本地request_id、飞书消息编号、授权范围和状态。相同商品公共候选可以复用，客户数量、收货地、预算和报价各自独立。
2. **先完成只读找货闭环。** 发出限定任务，Accio使用受支持原生工具执行，返回带本地request_id的严格结果封装；程序验证候选ID、链接、来源、MOQ和数量。不要把无结果或无任务编号当成失败后自动再发；缺证据进入待核查状态。优先继续核实正式外部API，若仍只有Agent原生入口，明确维护这层异步协议及其限制。
3. **单独验证询价和供应商关联。** 先取得正式工具schema、明确联系对象、内容和回执方式，再实现发送幂等、unknown原任务核查及供应商答复关联。当前没有执行真实供应商询价，不能预先宣称链路可用。
4. **在可核验报价上计算。** 保存供应商报价、规格、MOQ、币种、数量档、运费、税费、有效期及证据。报价规则由程序算，AI负责自然表达；缺报价或运费时继续待补充，不让AI把网页标价补成核实成本。
5. **最后接客户发送。** 初期人工审核报价，后续再按明确授权自动执行。沿用工作台现有身份、来源版本、整会话prepared/sending/unknown保护、最多三次未提交暂时错误重试，以及平台accepted证据；新采购任务不能绕过旧发送未决状态。
