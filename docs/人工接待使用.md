# 客户接待页：手写消息与自动接待

供接待业务员操作，介绍0.3.21的客户页，见[本版说明](0.3.21发布说明.md)和[验证记录](verification/0.3.21.json)。实际安装版本以程序窗口为准，最新公开版本以[发行仓库](https://github.com/juccistar/reception-workbench-releases/releases)为准。工作台始终保留正常人工聊天，手写发送不要求AI检查或切换独立人工模式。

## 从 Accio 授权环境启动

保存编辑并正常退出同一商家的已有窗口，然后在允许启动工作台的目标商家 Accio Work 授权 PowerShell 会话执行页面复制的当前EXE启动指令。指令使用 `--connect-from-accio`，按实际安装位置生成，不固定商家或数据根。执行后立即返回。不要复制令牌。新窗口继承当前授权，已有窗口不能通过再次执行命令取得授权。普通双击 EXE 默认进入合成演示。

便携包需完整解压，使用解压目录里的同名授权启动入口，无需安装 Python 或 Node。

## 选择客户、输入、发送

1. 完成读取检查，确认当前卖家及客户身份。
2. 打开客户会话，在回复正文中输入消息。首次编辑会立即暂停该客户的自动处理，其他客户继续。
3. 点击发送。程序先保存确切正文，再提交这一个请求；无需 AI 草稿审核或额外业务预检。也可用 Ctrl+Enter。
4. 查看发送结果和平台消息编号。任务排队只表示已提交处理，不表示平台已经受理。
5. 本条受理后可以继续补充，或主动跟进。上一条是卖家消息、采购条件尚未整理、全局自动接待暂停，都不会阻止普通人工聊天。

发送中继续输入的新正文会保留。客户发来新消息或后台出现新 AI 建议，也不能覆盖手写正文。切换客户、采购事项或退出前，先确认本地保存完成。

人工消息按会话保存，与采购事项的 AI 草稿分开。已受理消息纳入聊天历史，后续 AI 能看到；手写消息不会自行修改采购事实或创建飞书登记。

## 摘要、需求、建议和翻译

会话摘要显示在中间聊天区的客户标题下，概括本客户对话及需核实内容；它按会话保存，多项需求共用，无需求也能显示。右侧为中文采购需求和独立业务补充，窄屏使用统一抽屉。未读、待回复和需求进度分别显示，不把需求整理当成待回复。

在右侧填写或留空业务补充，正文为空时点击“生成回复建议”，正文非空时点击“润色当前回复”。补充自动保存，默认用于自动接待、建议和润色，不写成客户事实；覆盖或清空移除旧正文，变更使依赖旧版本的未提交结果失效。润色冻结未发送正文及版本，保留数字、价格、单位、币种和承诺条件。即使自动暂停、已人工接管、卖家最后发言、没有新消息、没有事项或需求缺项，只要身份和AI能力正常仍可生成。生成、查看或填写补充不会接管客户，也不改正文；生成及润色时在输入框上方直接显示处理框，结果未处理时持续保留。可替换、重新生成或弃用，替换和弃用后关闭，同一条已处理建议重开不再弹出。点击“替换到输入框”无需确认，会完整替换已有正文并接管，手写和人工发送也接管；回复仍由业务员发送。固定发送或结果未知时可以继续编辑下一条，但原发送内容不变，未决发送保护仍生效。

业务补充输入框左下角“＋”支持多选文件，也可粘贴截图或本地文件、拖入文件；普通文字照常粘贴。附件支持PNG/JPEG/WebP图片、PDF和UTF-8的TXT/MD/CSV，最多5个、单个6 MiB、合计20 MiB；PDF最多10页，单附件提取文字最多16000字符。图片缩略卡和中央原图卡均可右键复制全尺寸图片，原图支持适配／原始尺寸及点外、Esc关闭；底部上传和保存工具固定，正文与附件独立滚动。PDF/文本可查看提取内容，扫描或加密PDF不作已解析处理。附件按客户会话保存，默认用于自动、建议和润色；它们是商家补充，不是买家确认。移除或新增附件会更新补充版本，使旧未提交结果失效；预览成功不等于AI看过。

采购事项显示简短品类，完整产品描述和来源保留，同品类事项按各自编号区分。客户页、待报价和客户资料的日常需求区不再提供品类保存、逐项确认编辑、整理复核、候选应用、新建或移项表单；历史记录保留。原文更正会使相关事项旧依据失效。建议预览保留客户正文、中文译文、采用和必要的简短状态，不显示内部协助段落、质量分析长文或规则名单。

需求由AI直接用中文梳理，仅在新建或确需更新时返回变更；本轮没有变化就沿用已保存内容，补充条件只改对应字段，明确撤回才清空。多笔采购分别保存，提回旧产品时更新原事项；浏览旧事项不会改变后台默认事项或被后台更新强行切走。缺少依据留空，原文另作来源，不再增加一份中文展示值；客户预算与商家报价分开，无需字段齐全或逐项确认才能回复。聊天和有效人工建议可共用开关进行中文翻译，原文与译文并列并持久保存，失败可重试；译文不写入需求、编辑框或发送队列，也不改变接管状态。

需求区显示产品ID、程序派生的商品链接、客户产品图片及独立商品主图。数字ID自动生成国际站链接，完整显示，点击文字复制，旁边箭头使用系统浏览器打开；自定义需求可用“定制-数字”本地编号，不生成平台链接或读取平台图。商品图片由后台按图组顺序准备最多五张，缩略图支持放大和切换，界面不再常驻显示来源解释；后台保留请求绑定及排序证据，图片不替代客户图片。链接和主图均不进入接待指定上下文，商品页面也不作为经营承诺依据。

相同商家、平台及商品ID复用公共产品和一次采购任务，客户数量、地址、预算及业务补充独立。产品库可管理多个供货方案，并明确选一份用于当前需求；修改产品默认方案只影响以后新绑定的需求。内部进价不是销售价。采购授权独立于接待；目前定向供应商询价及报价回收尚未验收，页面明确显示不可用。

普通正文润色不准备历史图；自动接待和建议仅使用本会话各事项明确关联的产品来源图片或无竞争来源的单张买家图候选，商家图须有买家明确引用。获准图片不设固定张数上限，仍受默认64 MiB、准备60秒及并行2项预算约束。只有本轮确切读取记录可证明看过，图片线索不直接成为买家确认事实。高级设置可调整翻译、提问和按品类的待报价必填字段；产品始终必需，必填不阻止普通聊天。资料页可设置风格优先级，适用风格只选一份。

## 自动回复与发送进度

自动接待会按真人聊天的节奏组织一至三条回复，长短随语境变化。整轮生成后按顺序发送，每条取得平台受理回执才继续下一条；不需要业务员逐条确认或手动续发。

当前自动进度显示在聊天区域，包含发送、同步、确认结果或重试。完成提示短暂显示后收起，旧批次在折叠的发送记录中查看，可区分时间、自动／人工和每条结果。已发送数量按平台受理统计，不表示客户已读。结果未知时核查原操作，不重复发送。

人工输入始终是普通单条正文，建议和润色都处理整份正文；不再提供分条编辑、合并或提取自动尾部。自动进度与人工草稿分别显示，旧发送记录不会覆盖新输入。

## 恢复此客户的自动接待

客户标题右侧可直接恢复／暂停此客户自动接待，历史按钮点击后直接补全，不再弹解释卡片。人工介入后，该客户持续由人工处理。业务员明确恢复该客户的自动接待后，程序才会继续自动处理。全局自动接待也需要处于运行状态，且本客户在授权范围内。

“暂停自动接待”停止自动处理和自动发送，人工聊天仍可使用。关闭程序、账号或发送目标变化会撤销尚未提交的人工意图；已经提交的消息不能靠暂停撤回。

自动接待仍需读取及AI检查通过，并明确选择客户范围；当前授权内不限制AI和自动发送总次数。旧质量、待核实及待协助提醒已移除，需要业务员核实的内容写在会话摘要中。每条自动发送仍检查当前身份、来源和正文版本、人工接管、范围及原生结果；移除业务提醒没有取消这些检查。

直接在业务补充填写当前答案或安排，无需逐项打开协助表单。正常任务会核对有来源的续答，只有确切受理回执才记录已答复；暂停、人工接管或AI不可用时仍可保存补充。查看、复制、生成建议和填写补充不接管；采用、手写或人工发送接管。详细状态见[连续接待说明](自动接待连续性.md)。

## 结果未知时核查原操作

- 若显示发送中，等待原请求结果，不反复创建新消息。
- 若显示结果未知，到运行记录核查原操作。未知状态会保护整个会话，切换采购事项也不能绕过。
- 核查只查询原平台消息和账本，不重新发送。取得权威回执后会更新状态。
- 只有明确拒绝且确认没有提交的请求，处理原因后才能重新保存并发送。

退出会先撤销新权限，再等在途任务落库。不要直接结束进程以跳过等待。飞书可单独验收，本地聊天和采购需求保存不依赖飞书。
