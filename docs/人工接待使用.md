# 客户接待页：手写消息与自动接待

供接待业务员操作，介绍当前客户页。实际安装版本以程序窗口为准。工作台始终保留正常人工聊天，手写发送不要求AI检查或切换独立人工模式。

## 从 Accio 授权环境启动

保存编辑并正常退出同一商家的已有窗口，然后在允许启动工作台的目标商家 Accio Work 授权 PowerShell 会话执行页面复制的当前EXE启动指令。指令使用 `--connect-from-accio`，按实际安装位置生成，不固定商家或数据根。执行后立即返回。不要复制令牌。新窗口继承当前授权，已有窗口不能通过再次执行命令取得授权。普通双击 EXE 默认进入合成演示。

便携包需完整解压，使用解压目录里的同名授权启动入口，无需安装 Python 或 Node。

## 选择客户、输入、发送

1. 完成读取检查，确认当前卖家及客户身份。
2. 打开客户会话，在回复正文中输入消息。首次编辑会立即暂停该客户的自动处理，其他客户继续。
3. 点击发送。程序先保存确切正文，再提交这一个请求；无需 AI 草稿审核或额外业务预检。也可用 Ctrl+Enter。
4. 查看发送结果和平台消息编号。任务排队只表示已提交处理，不表示平台已经受理。
5. 本条受理后可以继续补充，或主动跟进。上一条是卖家消息、采购条件尚未整理、全局自动接待暂停，都不会阻止普通人工聊天。

发送中继续输入的新正文会保留。客户发来新消息或后台出现新 AI 建议，也不能覆盖手写正文。切换客户、采购事项或退出前，先确认本地保存完成。

人工消息按会话保存，与采购事项的 AI 草稿分开。已受理消息纳入聊天历史，后续 AI 能看到；手写消息不会自行修改采购事实或创建飞书登记。

## 0.3.1的建议与翻译

客户页右侧上方是采购需求，下方是业务补充；需求折叠时补充仍可用，窄屏放入统一抽屉。顶部固定入口可切换多个采购事项、定位原文，待报价也可进入指定事项。未读、待回复和需求进度各自显示，不把需求整理当成待回复。

在右侧填写或留空业务补充，点击发送左侧唯一的“生成回复建议”。补充自动保存并仅供主动建议使用，不写成客户事实或自动接待资料。即使自动暂停、已人工接管、卖家最后发言、没有新消息、没有事项或需求缺项，只要身份和AI能力正常仍可生成。生成、查看或填写补充不会接管客户，也不改正文；页面只显示最新成功建议。点击“采用到输入框”无需确认，会完整替换已有正文并接管，手写和人工发送也接管；回复仍由业务员发送。固定发送或结果未知时可以继续编辑下一条，但原发送内容不变，未决发送保护仍生效。

需求原始值、缺项、冲突和原文来源保留，客户预算与商家报价分开；无需字段齐全或逐项确认才能回复。可选中文展示不覆盖原值，历史译文按需缓存并可回退原文。聊天可开关只读中文翻译，原文和译文并列，失败可重试；不识别图片文字，不写入采购事实、编辑框或发送队列，也不改变接管状态。

## 恢复此客户的自动接待

人工介入后，该客户持续由人工处理。业务员明确恢复该客户的自动接待后，程序才会继续自动处理。全局自动接待也需要处于运行状态，且本客户在授权范围内。

“暂停自动接待”停止自动处理和自动发送，人工聊天仍可使用。关闭程序、账号或发送目标变化会撤销尚未提交的人工意图；已经提交的消息不能靠暂停撤回。

自动接待仍需读取及 AI 检查通过，并明确选择客户范围。0.2.22起不限制AI和自动发送次数。商业资料或正文数字依据问题会显示质量提醒，不会因此接管客户；真实采购事实仍单独核验。每条自动发送仍检查当前来源与正文版本、人工接管、范围及原生结果。某一条历史草稿的预演结果不是全局接待启动前置。

“待你协助”表示需要补充核实信息，AI仍可继续接待。查看、展开、复制建议和填写协助结果不会接管客户；“采用到输入框”、实际输入/发送或点击接管会暂停该客户。协助结果可保存为内部内容，或明确允许用于回复客户；只有后一种才能安排对客跟进。详细状态见[连续接待说明](自动接待连续性.md)。

## 结果未知时核查原操作

- 若显示发送中，等待原请求结果，不反复创建新消息。
- 若显示结果未知，到运行记录核查原操作。未知状态会保护整个会话，切换采购事项也不能绕过。
- 核查只查询原平台消息和账本，不重新发送。取得权威回执后会更新状态。
- 只有明确拒绝且确认没有提交的请求，处理原因后才能重新保存并发送。

退出会先撤销新权限，再等在途任务落库。不要直接结束进程以跳过等待。飞书可单独验收，本地聊天和采购需求保存不依赖飞书。
