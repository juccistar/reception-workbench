# 自动接待连续性

供接待业务员和维护人员使用，介绍0.3.13的连续接待及发送规则。实际安装版本以窗口核对，最新公开版本以[发行仓库](https://github.com/juccistar/reception-workbench-releases/releases)为准；当前实现见[本版说明](0.3.13开发说明.md)。

## 开启与权限

从当前商家允许使用工作台的Accio Work环境启动，核对商家及数据目录，完成当前连接的读取与合成AI检查，保存接待范围后明确开启，详见[启动与授权](自动接待启动与授权.md)。

当前授权内AI调用和自动发送不限总次数，界面继续保存统计。暂停不清零，保存范围或业务设置撤销授权，重启保持暂停。人工编辑只接管当前客户，恢复需明确操作；采购有独立授权，不能用接待授权代替。

## 常见状态怎样处理

| 状态 | 含义 | 操作及后续 |
| --- | --- | --- |
| 待回复 | 当前客户存在尚未受理答复的消息 | 按接待范围继续处理，也可直接人工回复；需求整理齐全不等于已回复 |
| 任务进行中或失败 | 同步、生成或发送任务尚在执行，或记录了实际故障 | 查看原任务及安全错误；排队、生成完成和平台受理分别判断 |
| 人工接管 | 业务员手写、采用建议或人工发送后接管当前客户 | 该客户自动处理暂停，需明确恢复；查看或生成建议、填写补充不接管 |
| 结果未知 | 原消息可能已提交，但尚无确切平台受理结果 | 核查原操作，不新建发送，不换事项或请求编号绕过 |

全局接待、人工归属、未读、待回复、采购进度及发送回执独立保存。0.3.13不再生成旧质量、待核实或待协助提醒状态；仍需业务员核实的内容写在独立会话摘要中，不把摘要当作人工已核实证据。

## 业务补充怎样用于跟进

直接在当前客户的业务补充中填写已核实的运费、库存、销售报价或沟通安排，只保留最新正文。补充默认用于自动接待、人工建议及润色，不作为客户预算或客户已同意的证明；内部条件不能直接逐字泄露给客户。

补充变更使依赖旧版本的未提交结果失效。自动接待已授权且买家来源、本机accepted卖家消息及最新补充可核验时，正常任务可生成有来源的续答，无需逐项打开协助表单或另跑分类模型。暂停、人工接管或AI不可用时仍可保存补充，不能因此恢复权限。

生成回复不表示已发送，只有相应草稿取得确切accepted回执才记录已答复。稳定来源/问题编号、原operation关联和失败预算继续用于防重；它们是内部执行证据，不恢复为日常问题提醒清单。更换补充版本、新job或重启不能重置同一失败链。

## 正文、摘要、需求及采购

需求由AI根据真实依据直接用中文归纳，缺项留空，原始消息与确切片段保留作证据。会话摘要概括已谈内容及需核实事项，按商家和会话保存，同会话多需求共用；润色只处理冻结正文，不更新摘要或需求。没有采购事项仍能人工聊天。

条件齐全进入待报价后仍可回答新增问题，普通聊天不会清掉已有采购事项。新产品ID原子建立公共产品、需求关联及一次持久采购任务；同商家同ID可共享公共供货资料，客户数量、预算、地址、聊天、补充和私发图片独立。

数字平台ID的链接由程序派生，定制-数字是本地编号，不生成平台链接。独立商品主图由后台安全读取，仅供展示和找货，不进接待上下文或语义指纹，不替代客户图片；当前采用平台图组首图作参考，不等于已证平台主图或SKU。

采购须另行授权，unknown只核查原请求，不因空链接、新客户、新job或重启重新找货。所选有效供货方案才能辅助接待，内部进价不是销售价；页面参考不能当供应商确认报价。当前自动定向询价及回复回收仍blocked，不能将任务建立或合成结果当成真实询价成功。

## 生成和同步暂时失败

可确定修复的输出格式问题可以整理，但不能猜造事实或把原始工具载荷当正文。无法得到完整正文时，保留实际任务及失败原因，按当前规则恢复；一个客户失败不应使其他客户退出接待。

通道可用、授权有效且仍有明确来源时，可先发送一次简短确认，再保留最终答复任务。简短确认不是最终答复，也不能绕过未决发送保护。新消息会使旧来源建议或重试失效，按最新来源重新规划；已经保存的人工正文不被新建议覆盖。

图片读取失败时不声称已看懂，仍可继续文字接待。商品展示图读取不占接待AI槽，采购等待图片时也不占该槽；真正的采购AI与接待仍共用本商家执行槽，后续模型请求可能排队。

## 自动发送重试与回执

同一商家、会话、来源消息及回复阶段的一条自动失败链最多三次总尝试。仅明确属于暂时错误且确认未开始提交时，按5秒、15秒退避；确定性或未分类拒绝停止本条重试。新任务、新草稿、补充版本变化和重启不重置预算，历史超限也不再重试。

prepared、sending、unknown保护整个会话，切换需求不能绕过。可能已提交或结果未知时只核查原operation，不能以剩余重试次数为由另发。accepted须有确切平台消息编号及提交证据，不能凭同文猜测；生成失败恢复与发送失败限次是不同环节。

身份或客户归属不明、客户明确要求停止联系、人工接管、范围不允许、全局暂停或已有未知发送时，不能自动提交新消息。保留实际原因和任务，不显示成已回复。退出、备份、迁移和恢复沿用[用户指南](USER_GUIDE.md)与[数据说明](DATA_AND_RUNTIME.md)。

## 经营资料与验收

产品、样品与Logo、交期、运输和售后等模板默认关闭，不自带可对客承诺的真实价格、库存或交期；填写、确认启用及适用条件后才进入当前商家上下文。

可用正文仍须依据可靠资料回答，未知内容等待核实；摘要归纳不等于人工确认。合成窗口、图片下载、只读商品接口、真实接待发送及供应商询价分别验收，不能互相替代。
