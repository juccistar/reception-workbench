# 使用与验收

本说明面向 0.4.2 使用者。实际安装版本以程序窗口为准；源码、窗口、候选和公开状态分别见[本版记录](verification/0.4.2.json)，公开下载见[发行仓库](https://github.com/juccistar/reception-workbench-releases/releases)。旧版本的验证结果保留在各自版本记录中。

## 启动台与账号

双击进入启动台，使用“全部 / 国际站 / WhatsApp”筛选账号。卡片显示状态，状态旁编辑名称和设置，直接“连接”或“打开窗口”。多个不同 WhatsApp 账号可分别运行，断开一个不会关闭其他账号。关闭有运行账号的启动台会隐藏到托盘，真正退出使用托盘操作。

国际站首次添加账号时，复制完整口令到目标商家的 Accio Work 授权会话执行。程序核验真实商家身份后登记并打开工作台；不要复制令牌。索引及上次核验时间不代表当前授权，已有窗口经本机握手核验后才能切回。需要重新授权时从对应商家会话启动；重连同一商家前保存并正常退出旧窗口。一个商家跨目录只能运行一个实例。

正式入口不提供 Demo。便携版须完整解压，使用包内程序与授权启动入口，无需另装 Python 或 Node。源码变化和公开发布都不代表本机已安装新版本。

## 共享模型与中文翻译

在启动台模型设置中添加 API，填写名称、协议、服务地址、模型 ID 和 Key，再分别为接待和翻译选择配置。可以共用同一配置。保存后的 Key 不回显，编辑时留空保持原值，也可明确清除。接待处理需求、摘要、自动回复、建议及润色；翻译用于聊天和有效人工结果。

开启自动接待、生成建议和润色都不要求先做 AI 检查，实际任务直接尝试当前配置。模型配置、认证、网络或输出失败时显示“AI不可用”，保留正文。取消、排队、来源变化和旧客户迟到错误不作为模型故障。需要诊断时可主动执行模型检查；它使用合成输入，可能产生费用，不自动发送客户消息，也不替各商家开启接待。

在商家工作台的“连接与设置 → 聊天翻译”启用当前商家翻译，核对实际商家、数据目录和服务。每个商家分别启用，迁移或恢复到新根后需重新确认。聊天译文与原文并列；建议及润色的中文译文独立于聊天译文显示开关。译文不写入正式需求、编辑框或发送队列，失败只显示简短状态。

配置在本机同一 Windows 用户间共享，Key 使用 Windows DPAPI 加密；业务库与备份不包含共享 Key。修改接待配置会撤销受影响的接待授权，仍须明确重新开启，不自动改用其他 API。

## 客户接待与人工聊天

主导航在各页面、聚焦聊天和收起资料时保持一致。客户列表提供搜索、筛选、消息摘要与状态，不显示头像。聊天消息时间保留完整的 `YYYY-MM-DD HH:mm:ss`；列表使用紧凑时间。会话摘要按客户保存，多笔需求共用，没有事项也可聊天。

输入、采用建议和人工发送会接管当前客户，其他客户继续。点击发送或按 Ctrl+Enter，程序先保存当前正文再提交一次，没有接管或普通发送确认弹窗。人工聊天不要求模型检查、已有需求、采购条件齐全或最后一句来自买家。发送期间的新输入不会被晚到回执或 AI 结果清空。

正文为空时生成回复建议，非空时润色当前正文。生成和查看不会接管、修改输入或自动发送。结果只有一份正文，可采用、重新生成或弃用；生成中可取消，旧结果不会覆盖新的请求。采用直接替换输入框并接管，仍由业务员发送。润色保留冻结正文的原意、数字、价格、单位、币种和承诺，不更新需求或摘要。

右侧显示采购需求和独立业务补充，可收起。拖动右侧边界调宽，拖动需求与补充间的分隔条调高，支持键盘调整并按商家保存。窄窗口使用抽屉。点击来源直接定位原消息；点击补全历史直接执行，只显示简短进度，执行中不可重复提交。补全旧消息本身不触发自动补答。

## 自动接待

在“连接与设置 → 自动接待”选择“全部客户”或“选中客户”。后者就地显示可搜索的客户清单。保存范围后，点击顶部按钮直接开启；顶部只显示运行状态与开启/关闭动作，不再启动 AI 预检或重复确认。全部客户包括后续客户，人工接待中的客户除外。旧 incoming 范围转换为全部客户后仍须明确开启，不恢复旧授权。

回复按聊天节奏自然组织一至三条，每条取得确切平台受理后继续。当前进度和结果显示在聊天里，完成提示随后收起；不提供发送记录或人工核查入口。接管、恢复直接执行，恢复仍要求全局运行且客户在所选范围内。

保存接待设置或范围、账号与来源变化会撤权，重启不恢复授权。关闭自动接待后仍可普通人工聊天和接收同步消息。新工作区默认每 2 秒检测活动、连续消息合并 1 秒，已有明确设置保留；这不是回复时延承诺。

## 发送结果与异常

本地保存、任务排队、模型生成、平台受理和客户已读分别判断。发送中等待原请求，结果未知时后台只沿原操作、原账号和确切平台消息编号核对，不按同文猜测，不换任务、事项或编号重发。未知状态保护整个会话，期间仍可编辑下一条。

只有确切未提交的暂时错误可沿原失败链按 5 秒、15 秒退避，总计最多三次尝试。新任务、草稿、补充版本或重启不能重置同一失败链。没有充分受理证据时继续待确认；升级不清除旧账本或补发历史消息。

后台断开时正文可留在窗口，恢复后核对保存结果。退出前保存编辑并正常关闭，程序撤销新权限并等待在途结果落库。

## 需求、报价与业务补充

需求固定 13 项，由 AI 依据真实对话用中文整理，缺项留空。只有确需建立或更新时才改变；明确撤回才清除。一个客户多笔采购分别保存，浏览旧事项不改变后台当前事项。预算与商家对客报价分开，需求齐全不是普通聊天前置。

待我报价的事项清单和详情独立滚动，选择事项不自动跳聊天。可查看已有产品及供货参考，填写同客户共享的业务补充，再返回聊天。接待和报价使用同一份补充；切页前保存编辑，冲突时保留本地正文并处理差异，不能静默覆盖其他更新。补充默认用于自动接待、建议和润色，不当作客户已确认的事实。

数字商品 ID 的完整链接由程序生成，点击文字复制，旁边箭头在系统浏览器打开。没有平台 ID 的明确自定义需求使用稳定的“定制-数字”编号，不拼平台链接。商品展示图与客户需求图片分开，最多五张，不能据此承诺在售、库存、价格、交期或 SKU。

## 图片与既有补充附件

聊天图片通过受控来源读取，可预览原图和重试，透明图片使用棋盘底。图片加载成功不表示模型看过；仅本轮实际编码证据表示请求带图。相关买家图及获准商家图与文字同轮处理，单次请求按确切来源去重。普通润色不准备历史图片。默认整批 64 MiB、准备 60 秒、并行 2 项，单图上限 6 MiB，仍须满足来源与身份约束。

业务补充的“＋”支持多选文件，也可粘贴截图、本地文件或拖入文件。支持 PNG/JPEG/WebP、PDF、UTF-8 TXT/MD/CSV，最多 5 个、单个 6 MiB、合计 20 MiB；PDF 最多 10 页，单附件提取文字最多 16000 字符。扫描或加密 PDF 不算已解析。图片可右键复制全尺寸内容，PDF/文本可查看提取内容。

附件继续归原客户，新增或移除会更新补充修订，使依赖旧版的未提交结果失效，不覆盖期间新正文。这里沿用既有业务补充附件，没有新增聊天附件发送、文件下载或中转入口。

## 产品、供应商与采购

有效新产品 ID 可原子建立产品、需求关联和一次采购任务。同商家同平台同 ID 共用公共产品与供货资料；客户数量、预算、地址、聊天、补充和私发图独立。产品、供应商、采购采用紧凑清单，按需打开详情。

采购中心保留自动找货及 1 至 3 家供应商上限，保存后再明确开启本次采购授权。采购与接待分别授权，重启均不恢复。已生成回复不必等待找货；任务未知时只核查原找货任务，不重新搜索。

供应商可新增和编辑；一个产品可有多个供货方案，一个供应商可关联多个产品。方案保存规格、MOQ、内部成本、币种、交期、包装、运费、税费、有效期、来源和对客口径。内部进价不是销售价，页面参考不是供应商确认报价。默认方案仅供新绑定需求继承，修改默认不改变已有客户选择；过期、禁用或数量不适用的方案不能支持承诺。

定向询价、报价回收、供应商聊天、RFQ、下单和付款没有开放；真实图搜及全量 SKU 尚待验收。

## 资料、设置与运行记录

资料与政策采用分类、文档清单和编辑区。内置六份规则、三份经营模板默认关闭，须查看、编辑采用并明确启用。未填写的价格或交期不成为经营事实。公开资料、内部接待依据、聊天风格和仅人工备注分别管理，人工备注不进入 AI；适用风格按优先级选择一份。

设置分为自动接待、聊天翻译、图片与上下文、平台连接、数据与备份、飞书登记、界面布局、版本与更新八类。图片资源、提问次数和按品类的待报价字段沿用既有能力，产品始终必需，这些条件不阻止普通聊天。维护诊断按需展开。

运行记录只展示连接、资料、采购等任务，不提供发送历史或手动发送核查。飞书是可选异步登记，先做只读检查再明确启用写入，不在界面填写访问令牌；飞书失败不阻断本地接待。

## WhatsApp 单聊与客户侧栏

连接账号后，在自有 Google Chrome 专用环境扫码；系统需已安装 Chrome，不复制旧 Electron Cookie。多个账号分别持有环境、后台和账本，同一真实账号不能换环境绕过所有权与原账本。

自动接待前核验旧接入记录，选择允许的商家及新联系人默认商家，相关商家工作台须保持在线。默认商家只在首条有效实时买家消息时确定，不批量改绑旧联系人。原网页或手机人工回复会接管当前客户；更改联系人商家建立新接待段并暂停，明确恢复后才继续。

原生客户侧栏跟随可靠的当前单聊，显示真实客户资料，可搜索关联已保存的国际站客户、接管、恢复并保存文本业务补充。补充按账号、聊天和商家分段，旧视图排队请求不能写入新视图；关联只读背景，不反写国际站。无法确定当前单聊时清空资料，联系人尚未登记时显示基础信息并禁用操作。

发送结果未知仍沿原账号和原操作核对，确切 ID 且 ACK≥1 才受理，不重发。关闭页面会断开相应账号，最小化可继续。WhatsApp 不提供群发、采购、飞书写入或反写国际站。

## 数据、备份与升级

在“连接与设置 → 数据与备份”核对实际目录。迁移前保存编辑、正常退出、完整备份并逐项验证；恢复只到空目标。消息、图片、SQLite/WAL、原生账本、回执及 unknown 必须整体保全，不能只复制一个数据库或把回执当缓存删除。Chrome 登录环境与业务备份分开，共享模型 Key 不在备份中。

现有数据库打开时不新增消息索引；0.4.2 新建的带索引工作区不保证由旧版严格校验接受，回退须使用兼容的完整备份，不能手工删索引或改关闭标记。备份失败、目录冲突、未来版本不兼容时保留原数据并停止，不悄悄建空库。

版本与更新页提供检查、下载和安装。安装重启前保存编辑、停止新接待、等在途结果并做完整备份；重启保持自动接待关闭。更新元数据采用固定 Ed25519 签名，Windows 代码签名以实际安装器为准，二者不同。

合成回归、窗口截图、公共扫码、真实模型效果、实号登录收发及供应商操作分别验收。详细流程见[授权启动](自动接待启动与授权.md)、[客户页操作](人工接待使用.md)、[数据边界](DATA_AND_RUNTIME.md)和[在线升级](在线升级.md)。
