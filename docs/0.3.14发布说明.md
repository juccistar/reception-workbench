# 0.3.14 接待规则修复与业务补充附件

日期：2026-11-13。供接待业务员、维护和验收人员阅读。本版已发布为最新正式版，见[发行页](https://github.com/juccistar/reception-workbench-releases/releases/tag/v0.3.14)及[验证记录](verification/0.3.14.json)。发行编号443807050，发布时间2026-11-13T04:17:22Z；实际安装版本以窗口为准。

## 接待规则修复

恢复0.3.13提示词重构中遗漏的有效业务规则，包括任务和输入权限边界、客户希望/商家能力/双方同意/实际执行的区分、询问与备选、否定与更正、样品与大货范围、知识/内部规则/风格/商家补充的用途，以及客户沟通语言、自然回应、每轮和逐字段提问上限。

自动接待继续按原始角色理解final和supplement续答，不把卖家收悉或商家补充改成买家新消息，不把生成结果当成已经发送。人工建议不恢复自动权限、不接管或改变正文。润色保留冻结正文的数字、币种、单位、条件、否定和确定程度，不擅自增加样品、报价、寄送、下单或联系团队等安排。

仍使用AI直接中文归纳的需求、原文依据和独立会话摘要，不恢复旧facts/display_value、质量提醒、待核实清单或逐项协助状态。商品链接由程序按数字ID派生，商品主图只用于展示和找货，不进入接待指定上下文或指纹；供应商内部进价不等于客户预算或销售价。

审核稿与静态运行模块同步生成，可用 `node scripts/sync-reception-prompts.mjs --check` 检查一致性。提示词版本为reception-0.3.14，并进入生成来源版本；仅有文档文字不能代替实际请求中的指令。

## 业务补充附件

业务补充增加图片、PDF及UTF-8文本文件，按商家和客户会话保存，服务于自动接待、人工建议和润色。附件是商家提供的补充，不是买家消息或确认，不与客户产品图片及程序商品主图合并。

文本/PDF仅提供实际成功提取的文字；图片通过同一主业务任务的read_compat通道读取，保存本轮确切读取证据，不增加独立识图AI任务。上传或预览成功不等于AI已看过。附件变更影响补充版本及生成指纹，旧未提交结果失效；移除后不再进入当前上下文。普通润色不补读历史聊天图，明确添加的当前补充附件只帮助理解冻结正文，不能据此插入新商务安排。

支持PNG/JPEG/WebP、PDF及UTF-8的TXT/MD/CSV；最多5个，单文件6 MiB、合计20 MiB。PDF最多10页，每个附件最多提取16000字符；加密、无文字或扫描PDF不能视为已解析。上传使用宿主原生文件选择入口，原始路径不交给renderer；移除只接受当前会话及附件编号。最终EXE的原生选择、三类文件预览/提取、移除、客户隔离、建议和重开流程已通过；测试只替换文件选择框以选中临时合成文件，业务IPC和随包后台实际运行。
