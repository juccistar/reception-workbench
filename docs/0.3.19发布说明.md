# 0.3.19版本说明

日期：2026-11-14。面向工作台使用者与维护人员。

状态：开发实现、定向回归和源码构建已完成，等待隔离窗口、公共扫码页验收。公开最新版仍为0.3.18。本版尚未打包、公开发布或安装替换；真实商家连接故障尚未复现，不能视为已修复。实际结果见[验证记录](verification/0.3.19.json)。

## WhatsApp失败后保留有效页面

继续使用左侧独立WhatsApp模块、原始网页和同一WebContentsView。SDK初始化失败时退役程序接待、释放本代回调和CDP连接，允许已确认可信的原始页面继续加载和展示。页面HTTP、网络、TLS、关闭及不允许的导航仍单独报告为页面故障。

页面可用与自动接待就绪分别显示。原始页面可用时显示“原始页面可用，自动接待未就绪”；页面仍在加载时显示“网页仍在加载，自动接待初始化失败”。失败详情按需展开，提供固定阶段、原因和本地诊断编号。只有宿主SDK就绪、业务账号有效且AI与后台健康检查通过时才能新开自动接待；原授权撤销后不会自动恢复。

宿主状态直接通知界面，避免慢业务查询遮住连接失败。查询和事件分别校验顺序，迟到查询不能覆盖刚收到的故障。

## 分阶段诊断与旧连接隔离

连接记录视图、CDP、认证准备、版本缓存、页面导航、网页模块、SDK注入、回调、扫码和就绪等固定阶段。故障可以区分协议失败、资源缺失、页面环境变化、网页模块错误及原有超时、HTTP与认证错误。首次二维码事件之后出现的SDK异常同样会被记录。

宿主在当前商家业务根的诊断目录保存受限JSONL，最多2 MiB×3份，并限制重复异常频率。只保存版本、阶段、固定错误码、异常类型和程序内相对堆栈位置；不写原始异常全文、聊天、联系人、账号、二维码、URL参数或凭据。诊断写入失败不会再次打断清理。

重连等待旧绑定清理，旧回调与超时不能控制新连接。完整文档替换会退役旧SDK并等待明确重连，避免在同一页面叠加注入。普通断开保留登录资料，HTTP 429继续遵循等待时间。

## 需求与发送规则

保持原有需求增量规则：只有确需新建或更新时输出和应用需求变更，无变化不重写需求。没有增加“空需求强制建单”、每轮重建需求或应用内旧数据清理。此前授权的一次性本机旧数据维护已经结束，维护工具和业务数据不进入本版。

WhatsApp继续处理全部入站单聊，国际站绑定仅作可选只读背景。SDK故障撤销对应自动接待授权；原发送操作、unknown和确切消息回执保留，不能换键重发。历史和联系人资料仍不触发自动回复。

## 验证范围

已通过57项桌面/宿主定向用例、32项后端定向用例、1项SDK生产资源闭包用例及类型检查。后端覆盖需求增量和WhatsApp账号、授权、发送防重与回执，未运行全量测试，也未调用真实AI或发送客户消息。

新增公共页验收使用实际编译宿主和固定SDK，无CDP预热，等待SDK注入结束并持续观察原始二维码至少60秒及一次刷新；另设首次二维码之后的受控SDK异常，验证降级页面持续可用。夹具只在内存替换业务启动入口，不代表真实商家启动、实号登录或收发验收。截图先遮去二维码等媒体，不保存二维码内容。

窗口验收使用真实renderer/preload与临时Demo后台，宿主故障状态通过事件替身输入；公共页面的SDK故障另在原始WebContentsView中验证。窗口和公共页的待执行结果在验证记录中分别保存。

真实商家原始故障、实际账号登录、重连、消息收发及ACK端到端验证仍未执行。公共扫码通过也不能替代这些验证。
