# 0.3.16 提示词及需求变更契约核对

日期：2026-11-13。供开发与验收人员使用。

本版把固定整份 requirements 输出改为可选的 requirement_changes，新增同会话事项目录与 reply_case_refs。审核稿由 scripts/sync-reception-prompts.mjs 生成静态 reception_prompts.py，运行时不读取文档。

| 原有规则或要求 | 本版对应位置与行为 |
| --- | --- |
| 希望、能力、双方同意、实际执行分别判断 | P01【事实与意图】完整保留 |
| 禁止编造、擅自承诺、虚称业务进度 | P01【事实与意图】、P03、P04 保留 |
| 询问、备选、未定、否定、更正及样品／大货范围 | P01、共用【需求变更与归属】和 P04 保留 |
| 资料用途、商家补充与附件来源 | P01【资料用途】保留；各事项目录按自身范围提供适用资料 |
| 内部进价与销售价分开 | P01【商品、图片与供货】及需求变更模块保留；来源校验限定回复涉及的事项 |
| 工具权限及真实图片读取证据 | P01、条件 P05 及需求变更模块保留，预览／复制不赋予 AI 读取证据 |
| 每轮及逐字段提问限制 | P01【对话与进度】保留 |
| 中文正式需求与真实连续原文依据 | 需求变更模块沿用 value、evidence_ids、source_excerpts；不恢复 display_value |
| 既有需求不因本轮未重复而清空 | 需求无变化省略；更新只列改动字段，clear_fields 须附撤回／更正原文 |
| 商品 ID、定制编号及程序链接 | 买家来源、定制编号稳定复用、不输出 product_url、不查商品继续保留 |
| 无采购也可有独立摘要 | P02、P03 继续独立生成摘要，不由需求变化推导 |
| 生成建议不接管、不发送、不改输入框 | P03 及程序流程保留；需求保存与采用／弃用分开 |
| 润色只保留冻结正文含义 | P04 保留，不加载需求变更模块，不发布需求、归属或摘要 |
| 不恢复旧质量／协助提醒 | P01、各输出契约保留，必要未决内容写会话摘要 |
| 同客户多个采购事项 | 使用本轮 case_ref；旧事项继续更新，新采购有独立来源，不靠当前默认事项猜测 |

P02 和 P03 删除的是“每轮必须输出整份 requirements”的格式要求及其重复定义；有效字段、事实与来源限制移入共同的需求变更模块，由生成脚本保证两种任务都实际携带。P04 不加载该模块，避免把不适用的需求整理规则附加到润色任务。

模型输入中的正式需求记录和平台原始卡片分别投影，保留已保存的 product_id 和允许媒体引用，继续排除程序派生链接及商品展示图。固定规则不包含经营事实，程序已排除的对象不额外加入模型解释。

当前自动、普通建议、润色、final、supplement 及内部兼容请求装配定向检查通过。该结论核验实际指令与解析链路，不等同于真实模型语义或平台验收。
