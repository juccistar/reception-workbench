# 0.3.18开发方案：内嵌WhatsApp连接修复、浏览器兼容、后台保活与提示精简

日期：2026-11-14。面向开发、维护及验收人员。

状态：0.3.18已完成实现及定向验证，继续现有Electron内嵌路线，公开发行仍为0.3.17。实际公共页发现附加产品标记还会触发浏览器不支持页；最终采用真实Chromium标准标识，HTTP 200及SDK扫码事件已通过。最终构建与窗口状态见[验证记录](verification/0.3.18.json)。正式登录环境及真实业务数据未改动。

## 1. 本版目标与架构选择

本版交付四项：

1. 修复WhatsApp登录页HTTP 400，完善连接错误、超时及取消处理。
2. 校正内嵌浏览器与单页CDP适配的环境信息，补齐同页面兼容验收。
3. 保护后台执行循环，增加独立健康检查和受限诊断，避免队列停止而界面仍显示正常接待。
4. 删除聊天区整个图片覆盖提示区。

继续使用左侧独立WhatsApp模块、原始WhatsApp Web、单个WebContentsView和同页面whatsapp-web.js/Puppeteer。沿用当前商家隔离的persist partition、SDK固定版本及发行归档，不引入第二浏览器、LocalAuth或登录目录迁移。

国际站与WhatsApp的接待控制分别保存。WhatsApp自动接待继续覆盖当前账号全部入站单聊，包含未绑定客户及后续新联系人；国际站绑定仅提供只读背景。WhatsApp消息、摘要、操作和账本仍独立，不反向写入国际站或触发采购、询价、飞书。

真实Chrome路线已完成[比较评估](WhatsApp真实Chrome与内嵌路线评估.md)，本版采用内嵌路线。浏览器环境扩展项见[兼容候选方案](WhatsApp浏览器环境与自动化兼容候选方案.md)，其正式项与实验项以本方案划定的范围为准。

## 2. 已确认依据与仍有的限制

- 正式程序调用`app.setName('询盘接待助手')`，Electron默认User-Agent含中文产品标识。同一代理、Electron和0.3.17版本的临时会话对照中，中文标识返回HTTP 400；ASCII标识返回200。保留中文应用名，仅替换请求头中的产品标识也返回200。证据：`artifacts/verification/wa-http-20261114-b/report.json`。
- 修复前ViewTransport的`Browser.getVersion`固定返回Chrome/140，实际运行内核是Chromium 156。这是内部CDP适配信息差异，与发给WhatsApp的HTTP User-Agent分别处理。
- 合成环境中，调度入口未捕获异常可终止业务线程，而状态查询仍可用、接待标志仍开启，后续同步任务全部queued且未开始。原真实故障的异常堆栈没有留存，不能将合成异常当成实际历史根因。证据：`artifacts/verification/worker-20261114-synthetic-exit-proof.json`。
- 当前启动恢复已会取消旧queued/running同步任务，发送操作保留原编号与unknown核查路径；不需要以手工清理真实库作为修复前置。
- 图片红框来自`Reception.tsx`的`photo-coverage`折叠区，显示最近任务的准备情况，容易与当前聊天即时状态混淆。

## 3. WhatsApp连接修复

### 3.1 规范客户端标识

- 保留中文应用名、窗口标题及导航文字。
- 在WhatsApp首次网络导航前使用实际Chromium生成的标准浏览器User-Agent，移除附加的应用产品名及Electron产品token；Chrome版本、操作系统及WebKit等原生内容保持实际值，不硬编码或冒用其他版本。应用/Electron版本继续保存在本地版本与诊断信息中。
- 保持SDK的`userAgent: false`，防止SDK默认旧Mac/Chrome 101标识覆盖实际环境。
- 同时设置WhatsApp专用partition的会话标识与视图标识，覆盖Worker和文档请求，不修改其他页面或商家的会话。
- 验收实际发出的请求头，同时核对页面所见标识；不以宿主字符串生成正确代替网络验证。

### 3.2 错误页停止初始化

- 检查`page.goto()`的HTTP响应，确认页面有效后再进入SDK注入。
- HTTP 4xx/5xx直接记录对应连接失败，错误HTML不继续初始化；预期导航无有效响应且无法确认有效文档时返回受限错误。
- 区分HTTP失败、浏览器不支持页、网络/TLS错误、导航超时、SDK引导超时和认证失败。应用模块准备时识别中英文浏览器不支持提示，返回固定`browser_unsupported`原因，停止SDK注入。
- 页面显示固定短提示，例如“登录页请求失败（HTTP 400）”“连接超时，请重新连接”。日志不输出原始响应正文或完整异常文本。
- 401/403、认证失效及账号限制不自动尝试；429遵循服务端等待信息，不进行密集重连。普通失败由用户明确重新连接，不无限重试。

### 3.3 有限等待与连接代次

- 网络导航、页面应用模块准备、SDK引导分别默认60秒；认证完成后等待ready默认60秒。模块准备完成后重新开始SDK阶段计时，均可被断开、宿主关闭或新连接代次取消。
- 正常二维码展示属于等待用户扫码状态，不套用总连接超时；扫码后进入认证/ready阶段。二维码自然轮换不当作连接失败。
- 超时处理须释放旧监听、计时器及CDP连接；仅`Promise.race`超时而后台继续注入不视为完成取消。
- 旧导航、旧注入、旧history及旧ACK不能改变新连接状态；用户连续点击连接不产生第二个宿主或消费者。
- 普通断开/关闭保留登录目录；清空资料或退出账号不得成为错误恢复的隐含步骤。

### 3.4 受限状态契约

宿主状态增加可选受限错误字段，例如`error_code`和`http_status`。同步核对shared DTO、主进程事件、preload及WhatsAppPage；保留已有账号与connection_epoch核验，不向renderer暴露任意CDP、脚本、请求头、Cookie或文件接口。

## 4. 浏览器环境一致性与单页兼容

### 4.1 本版正式修正

- 校正ViewTransport的`Browser.getVersion`，从当前受控WebContents的原生CDP信息获取版本；需要补充字段时使用实际运行环境，不再固定返回Chrome/140。
- 保持Browser/Target虚拟化仅映射当前WebContents，不能因补齐版本信息扩大为任意页面、任意浏览器目标访问。
- 核对HTTP User-Agent、页面标识、Client Hints及真实引擎版本之间的关系。保留引擎原生信息，不凭空补造Client Hints。
- 核对平台、语言、时区、窗口尺寸与DPR，优先沿用真实系统和视图配置。
- 验证可见页面与SDK操作同一DOM、同一会话；预注入、回调绑定和重连后监听只作用于当前页面。
- WhatsApp视图关闭后台节流，保证隐藏或遮挡时仍可执行接待所需脚本；验证切换模块、窗口缩放以及抽屉/模态遮挡后，显示与隐藏正常，后台连接不因普通页面切换而断开。

实际公共页对照发现，只将中文产品名改为ASCII虽可取得HTTP 200，页面仍可能显示“WhatsApp支持Google Chrome 100及更高版本”，在无CDP/SDK的原始页面中也可复现。最终移除附加应用/Electron产品token、保留真实Chromium标准标识后，HTTP 200、原始二维码及SDK扫码事件全部通过；对照记录保留，不把该浏览器识别问题当成账号限制或通用防封结论。

### 4.2 自动化兼容实验的交付边界

原候选方案中的自动化环境审计纳入本轮：在临时会话/受控页面检查SDK预注入、权限查询及必要浏览器API差异。基线记录只保留定位所需的版本、布尔检查和受限差异摘要。

涉及改变页面自动化特征或引入兼容插件的处理继续逐项评估。只有存在明确兼容问题、单项处理可复现地改善该问题且未破坏同页SDK与发送语义，才可形成默认关闭的宿主实验项；不将未经验证的插件安装和全套补丁当作正式修复依赖。正式版本保持真实环境信息，保留原生Canvas、WebGL、Audio输出。

每项实验记录修改点、受控对照结果、SDK回归及回退方式；没有满足条件的处理可以不进入交付，不以“处理更多指纹”作为验收目标。遇到认证或账号限制停止尝试，不通过切身份、换出口或清登录资料继续试探。

whatsapp-web.js仍是非官方接入。本版验收结论是页面加载、环境一致性与SDK兼容，不宣称不可识别自动化或保证不封号。

## 5. 后台执行保活、健康状态与诊断

### 5.1 覆盖完整执行循环

保护调度、取队列、业务进入、分派、插队、任务收尾和退出清理。重点核对`_work_loop`、`_yield_to_ready_work`及`_run_queued`现有异常处理的衔接。

- 可隔离的单任务失败：完成对应任务状态及清理后，同一业务线程继续处理后续工作。
- 调度等循环阶段异常：记录阶段与受限堆栈；可证明没有破坏队列/提交状态时，在原线程内有限退避恢复。同阶段连续失败前三次之间分别等待1秒、5秒，第三次仍失败转为执行异常；一次正常完成该阶段后重置其连续失败计数。
- 队列所有权、unfinished计数、AI槽和`task_done()`必须一一对应，不能在新兜底中重复结算。
- 无法确认队列、数据库或提交状态安全时，停止新增自动发送并明确报错，保留未决操作等待正常重启恢复。
- 外层`finally`负责必要清理，诊断写入失败不能再次终止清理。

调度故障预算独立于现有发送尝试预算，不增加真实提交次数。本版不在进程内自动创建替代执行线程，避免与原线程或在途操作并行。

### 5.2 独立健康检查与界面反馈

健康检查由独立于业务消费者的轻量检查执行，状态读取使用独立短锁或线程安全快照，不能排在长AI请求或同一业务队列后。

Snapshot新增独立`executor_health`投影，包含线程存活、健康状态、阶段、当前任务编号、最近进展时间、队列数量和受限错误码。正常空闲、执行、等待外部操作、异常恢复、无进展和线程退出须可区分；具体枚举在shared DTO与Python中统一。

- 阶段持续时间按该外部操作已有超时预算判断，不用2秒消息探测间隔判定卡死；正常AI等待及无任务空闲不误报。
- 确认线程退出或执行安全无法保证时，撤销国际站和WhatsApp的自动发送授权并使旧未提交生成失效；两条接待通道平时仍各自控制。
- 健康状态独立于授权、未读及采购状态，不通过改写`reception.running`掩盖异常来源。
- 顶部状态、设置页和WhatsApp接待开关一致反映执行异常，显示“后台执行异常，自动发送已暂停”，不继续显示正常接待。
- 受异常执行器影响的新任务明确返回未就绪；可用的本地查看、编辑和保存继续可用，输入正文及未决回执保留。
- 健康恢复或重新启动不自动重新授权发送。看门狗不重排可能仍在执行的任务，不创建第二消费者。

### 5.3 保留启动恢复

继续将旧进程遗留的queued/running同步任务取消，再由活动监测安排确有需要的读取。发送操作保持原编号及原核查路径，不新增“全部queued重新执行”，不清空unknown，不以新job或新操作键绕过防重。

### 5.4 可定位的受限日志

- 保存时间、应用版本、线程/阶段、任务编号、受限错误码、异常类型及文件/函数/行号组成的堆栈帧。
- 文件路径规范为程序相对路径，避免记录用户目录；不保存源码行文本、局部变量和原始异常全文。
- 不直接转存原始stderr，不记录聊天正文、草稿、提示词、原图、二维码、Cookie、Token、Key或完整请求头。
- 线程异常兜底复用同一受限格式，普通日志失败不影响业务；商家私有诊断目录按2 MiB×3份轮转，并对重复故障限频。
- 运行记录保留简短错误、时间和阶段，不在聊天区增加常驻技术说明。业务提交账本和回执仍整体备份，诊断日志不能替代它们。

## 6. 删除图片覆盖提示

删除聊天区整个`photo-coverage`折叠块，包括“本次图片覆盖：0/1张原图已准备”以及展开的读取说明；一并清理仅该块使用的样式，不留空行、不换成另一条常驻提示。

图片下载、原图准备、AI本轮实际读取证据、来源核验、预算和发送保护继续执行。必要的失败原因留在运行记录。摘要及书本图标、聊天原图、右键复制、业务补充附件、商品图重新采集和既有建议/润色交互继续沿用。

## 7. 核心业务回归边界

- 自动接待由新入站单聊触发；历史消息和联系人metadata不触发自动回复或人工接管。
- 原生页面、手机人工回复接管对应客户；程序回显按确切消息编号关联。
- 提交前持久冻结账号、连接代次、目标和正文，同单聊未决发送保持互斥。
- 确切消息ID且ACK>=1才能受理；unknown只核查原operation，不按同文猜测，不换键重发。
- 断线、账号变化、重启及明确执行异常撤销自动发送授权；重连和健康恢复不自动重新开启。
- 国际站保留正常发送的本地业务检查，不恢复已删除的发送前平台历史重读或Ready/Seal前置。
- 原始页面人工操作不等于程序自动发送能力可用；界面不声称能够锁住WhatsApp原生输入框。

## 9. 实施顺序与验收

1. 完成WhatsApp请求头、HTTP检查、阶段超时/取消和错误DTO，同时校正CDP版本信息。
2. 补齐临时会话环境基线、同DOM/同会话证明及连接生命周期定向用例，再按条件评估独立实验项。
3. 完成后台执行保护、健康检查、界面反馈和受限日志，回归旧任务恢复及两条通道撤权。
4. 删除图片覆盖区，检查宽窄布局。
5. 按影响范围执行定向测试、类型检查及必要构建；未经明确要求不运行全量测试。固定提示词不属于本版改动目标。
6. 实施进入候选打包时使用新的空输出目录。每次版本构建完成后按项目持续授权立即创建中文commit，写明0.3.18与主要变更，提交前核对范围、敏感文件和`git diff --check`；最终验证记录及时另行提交保存。
7. 在最终EXE及其SDK归档上核验正式中文应用名、扫码页与宽窄窗口，截图逐张查看。记录所测范围和未执行项目。安装、公开发布、默认入口晋级及真实数据迁移分别按后续明确指令执行。

定向测试入口优先覆盖既有`whatsapp-host-lifecycle.test.ts`、`whatsapp-coordinator.test.ts`、`whatsapp-ledger.test.ts`、`whatsapp-page.test.tsx`及后端`test_execution_0310.py`、`test_message_monitor.py`、`test_whatsapp_0317.py`的相关用例。新增必要的传输版本、执行异常和日志保密用例；不为纯展示删除堆叠镜像实现的测试。
