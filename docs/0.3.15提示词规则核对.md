# 0.3.15 提示词规则核对

范围：Accio 接待固定提示词及实际请求装配；不假定模型具体版本。对照 0.3.14 审核稿、0.3.15 方案第 2 节和现有装配代码。独立翻译、旧图像观察及未来原生附件兼容文本未改动。

| 原段落 | 原用途及处理 | 实际保留位置 |
| --- | --- | --- |
| P01 任务边界 | 限定生成和工具权限及抵御输入中的指令；保留。 | COMMON，三种任务均装配；有图时另追加 P05-B。 |
| P01 事实与意图 | 区分客户希望、商家能力、双方同意和实际执行；保护询问、备选、否定、更正、样品及大货，不编造能力、费用、库存、交期、认证或进度；全部保留。 | COMMON。 |
| P01 资料用途 | 区分 knowledge、guidance、style 和商家补充用途、版本冲突及商家附件不代表买家确认；保留。 | COMMON。 |
| P01 商品第一段 | 商品展示图用途属于程序内部解释，删除；商品链接、ID及页面信息的证据限制、空字段和重复 ID 不授予查询权限仍保留。 | COMMON 商品段；P02/P03 的商品输出和查询限制。 |
| P01 图片第二段 | 不再逐项枚举其他客户的资料，改为只使用当前客户资料；保留真实买卖方来源、商家补充、真实读取证据和不能从图片推断材质、尺寸、价格等限制。 | COMMON；有图时 P05-B 和清单。 |
| P01 供货、对话和输出 | 可用供货口径、内部进价、问句上限、发送受理、真实来源及 JSON 限制均保留。 | COMMON；各任务输出模块。 |
| P02 自动采集 | 删除程序派生链接及商品主图的内部说明；保留不输出 product_url、平台标题、不搜索商品、ID 依据、商家补充图片不充当买家需求图，其他续答、事实、需求、摘要、动作和输出规则保留。 | AUTOMATIC_TASK。 |
| P03 人工建议 | 删除程序派生链接及主图说明；保留不输出 product_url、不查商品、不猜平台标题，以及 ID、商家图片来源、建议不接管不发送和需求摘要规则。 | MANUAL_TASK。 |
| P04 润色 | 删除程序商品主图的具体说明；保留不要求补读历史聊天图、补充图片必须真实读取，以及冻结正文的数字、链接、条件、否定、承诺和商务含义。 | POLISH_TASK；COMMON 限定只读清单路径。 |
| P05-B 兼容读取 | 删除未使用附件模式和未入清单的商品图、SKU 图等枚举；保留只能读取清单确切路径、不读取其他内容、每条路径一次、工具参数限制、发送方与补充附件归属、读取成功证据、视觉限制及来源输出。 | IMAGE_COMPAT 仅在有实际图片输入时追加。 |
| REQUIREMENTS 兼容整理 | 删除派生链接和主图说明；保留不输出 product_url 或平台标题、不查询商品和来源限制。 | REQUIREMENTS_TASK，旧内部入口。 |
| P05-A、P06–P09 | 原生附件是未启用兼容入口，翻译、旧观察和固定收悉有各自契约；其文本未改，正常文本接待不会加载图片模块。 | 保留原兼容入口；当前图片请求使用 P05-B。 |

装配核对：`live.py` 的 `generate` 使用 AUTOMATIC，`generate_manual` 根据冻结正文选择 MANUAL 或 POLISH；`_business_query` 无图时调用 `model_request`，有图时转 `business_images.query_business_images`。后者验证聊天图片的 message_id、role 和发送方，补充附件以 origin、attachment_id 和 seller 角色建清单，然后将 IMAGE_COMPAT 与确切路径追加至同一请求。`model_payload.py` 按任务投影；润色保留冻结正文，且不带需求与商品上下文。图片是否真实读到仍以原有执行轨迹证据为准。程序商品展示图片隔离、授权、来源版本、发送防重及 unknown 核查继续由原程序实施，本次未更改。

定向测试使用合成数据和替身，检查三类文本请求及图片请求中的约束与角色；不证明真实模型遵循语义，也不证明真实平台图片读取效果。
