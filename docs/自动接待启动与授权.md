# 自动接待启动与授权

本文描述 0.4.2 的日常操作，实际安装版本以窗口为准。客户页始终支持普通人工聊天，不要求 AI 检查或独立人工模式，见[客户页操作](人工接待使用.md)。

## 从目标商家授权环境启动

双击进入启动台。添加国际站账号时，复制宿主提供的完整三段口令，到目标商家的 Accio Work 授权会话执行；程序核验身份后登记并打开工作台。正式入口不提供 Demo。不要复制令牌或扫描其他账号。若当前环境不支持启动，核实受支持的接入方式，不换渠道代执行。

启动台可打开经本机握手核验的已有窗口，商家登记和上次核验时间不代表当前授权。需要重新授权时从对应商家会话启动；重复命令不能向已有窗口注入新授权。重连同一商家前，先保存并正常退出旧窗口。不同商家可分别保留窗口，同一商家跨数据目录排他。

从工程目录也可执行：

```powershell
& '.\授权启动接待.cmd'
```

需固定卖家时使用 `--expect-seller` 及真实数字 AliID，不把账号目录编号当卖家 ID。新窗口只核验身份和读取，不自动发送；核对当前卖家、实际目录和客户归属。

## 配置模型

在启动台模型设置中添加 API，为接待和翻译分别选择配置。保存 Key 后不回显。开启自动接待、建议及润色都直接尝试当前配置，不要求启动 AI 预检或已有 passed 记录。身份、模型配置修订、来源和预算仍由程序核验。

模型检查是可选诊断，使用合成文字或图片调用真实 API，可能产生费用，不读取客户正文、不发送客户消息或写飞书；独立检查不改变当前接待授权。配置变化会撤销受影响的接待权限，保存配置不自动开启接待。

## 保存范围并直接开启

在“连接与设置 → 自动接待”选择：

| 范围 | 行为 |
| --- | --- |
| 全部客户 | 覆盖当前及后续客户，人工接待中的客户除外 |
| 选中客户 | 就地搜索、勾选明确客户，仅处理所保存名单 |

保存范围后，使用顶部按钮直接开启或关闭，无额外启动向导、AI 预检或重复确认。保存范围本身不启动接待；selected 空集合不能开启。旧 incoming 转为全部客户后仍须明确开启，重启不恢复旧授权。

当前范围内不限 AI 和发送总次数，继续保存统计；取消次数上限不改变图片、上下文、HTTP 或失败重试预算。人工编辑只接管当前客户，其他客户继续；恢复直接执行，仍要求全局运行且本客户在范围内。暂停不清统计，保存设置或范围会撤权。

## 观察结果与异常

自动接待先回应当前话题，再按依据整理需求和摘要。回复自然组织一至三条，每条取得平台确切受理后才继续，不需逐条确认。聊天只显示当前进度和结果，没有发送记录或人工核查入口。生成完成、本地保存、平台受理和客户已读分别判断。

实际模型配置、认证、网络或输出失败时提示“AI不可用”并保留正文；取消、来源变化、排队和旧客户迟到结果不误报。补全历史直接执行，只显示简短状态；旧历史回填本身不触发自动补答。

结果未知时后台沿原操作和确切消息 ID 核对，不按同文猜测或换请求重发，整会话的未知保护继续存在。真实新买家触发、AI 效果和平台回执须在明确对象与范围内单独验收，合成消息不能算实号闭环。

## WhatsApp、采购与飞书

WhatsApp 在启动台连接真实 Google Chrome 独立账号，选择允许商家并完成既有接入记录核验后开启。当前客户通过原生侧栏关联、接管、恢复和保存文本补充，账号与商家分段独立；没有增加反写国际站、群发或聊天附件接口。

采购授权与接待分开，未知找货结果只核查原任务。内部进价不是销售价；定向询价、报价回收尚未开放。飞书为可选异步登记，先只读检查，再明确启用写入，不阻断本地聊天。

退出前保存编辑，程序撤权并等待在途结果落库。备份和恢复使用完整数据入口，保全消息、图片、WAL、账本、回执和 unknown；不因退出或升级删除原操作。详见[用户指南](USER_GUIDE.md)、[现行规则](CURRENT_RULES.md)和[连续接待](自动接待连续性.md)。
