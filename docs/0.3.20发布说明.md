# 0.3.20发布说明

本版修复国际站分条回复遇到活动同步时停止尾部的问题，并增加WhatsApp网页数据库错误识别及受控登录环境重建。源码、候选及公开状态以[验证记录](verification/0.3.20.json)为准。

## 分条回复

- 全部业务和授权条件有效、唯一拒绝原因为会话尚待同步时，当前条目进入“正在同步会话，尚未提交”。同步完成后核对原来源和原条目，再决定是否继续；已受理的第一条不重发。
- 等待最多60秒，期间释放执行线程，其他客户和人工聊天可以继续。没有创建operation的等待不计发送尝试；已经创建但明确未提交的操作仍计入当前条目最多三次总尝试，既有5秒/15秒通信退避保留。
- 通信令牌缺失、撤权、人工接管、来源或业务依据改变分别处理。历史通用auth不会因升级自动变成可重试状态。unknown继续核查原操作。
- 已停止的自动批次增加“取出未发送内容”。程序核对全部未提交证据后只把未发送尾部写入人工草稿，供使用者查看再手动发送；已发送前缀不进入草稿，已有新输入不覆盖。

## WhatsApp

- 网页报告数据库错误时直接提示，不再把存在扫码占位画布当成页面可用。主文档替换显示网页重新加载及发生前阶段；可信注销导航继续完成，旧SDK和授权退役。
- 点击“重建WhatsApp登录环境”后，由宿主原生确认当前商家，为其建立新的登录分区，需要重新扫码和明确开启接待。正常升级及普通连接继续复用原登录分区。
- 重建等待在途发送、回执及旧连接收尾，保留旧目录和全部业务消息、需求、绑定与发送账本。配置写入失败不切换；已提交新代次后重启沿用新代次，不自动恢复接待权限。国际站接待独立继续。
- 旧账号未决记录仍有受限提示；更换登录账号不能代替原账号核查或清除unknown围栏。

## 验证与边界

后端相关文件最终定向复测合计173项通过，桌面及宿主相关文件最终复测合计165项通过，类型检查通过。此前一次后端Node桥用例因PATH缺失跳过，补齐既有Node路径后单独通过；一次配置写入失败测试的ESM替身不兼容已修正并复测通过。未运行全量测试。

源码实际窗口、最终候选EXE、公共扫码持续与刷新、SDK归档、固定更新签名及公开附件核验正在执行，实际结果逐项更新到验证记录。窗口中的同步等待投影和WhatsApp故障状态使用合成夹具；人工尾部提取通过真实Demo业务接口执行。

原WhatsApp异常持久会话的最初触发状态仍未唯一定位。本版提供保留旧资料的新登录入口，不宣称修复了某个已确定的数据库物理损坏。此次未对真实商家重建、登录或发送；公共扫码通过也不能替代实号登录收发验收。提示词正文未改，不安装替换本机程序、不迁移或清理真实业务数据、不推送私有源码。
