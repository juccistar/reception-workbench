# 自动发送通道简化

状态：2026-11-12 基于 0.3.7 完成修改，先纳入并核验 [0.3.8 本地候选](0.3.8发布说明.md)，现已包含于 [0.3.9](0.3.9发布说明.md)。实际公开交付及验收范围见[本版记录](verification/0.3.9.json)；0.3.7 安装包不包含本修改。本文面向维护人员及接待流程确认。

## 执行方式

正常消息同步 → Accio 生成回复 → 完整本地业务检查 → 核验身份并取得目标会话通信令牌 → 直接提交 → 保存确切消息编号并确认回执。

常规自动回复复用现有聊天提交接口，内部仍标记为自动接待，不改变人工接管、范围或统计。简短确认、正式续答和协助结果跟进使用同一提交机制，阶段关系及本机受理凭据仍核对。

## 保留的业务检查

- 当前商家、买家、会话和采购事项归属。
- 本轮连接及 AI 检查、接待/自动发送开关、授权批次、客户范围和授权起点。
- 客户接管、停止联系、事项关闭、消息同步待处理和本地消息时间有效性。
- 本地最新来源、确切正文与草稿版本、会话/需求版本、资料、业务补充及图片依据版本。
- 正文非空、长度与格式；正文语义质量仍只作提醒。
- 同会话未决发送、已受理来源防重，以及原有自动失败链次数和退避。

这些规则仍由接待服务在排队及提交回调中执行，不依赖发送前额外的平台历史读取。暂停、退出、接管和已同步的新消息或依据变化仍可阻止旧意图提交。

## 移除的发送前流程

常规自动发送不再生成账号级 Ready 快照，不调用 run/read-ready/seal-reply-preview/send-message 链，不逐条比对历史消息、商品卡片展示及时间，也不在封装后重读整段历史。续答同样不再在提交前读取平台历史，改用本地来源回调及本机已受理记录校验阶段。

尚未同步到本地的新平台消息可能晚于当前回复被发现。用户已接受这一取舍；正常消息监测和同步继续运行。

## 提交、回执和兼容

通信令牌只在内存及宿主自有 stdin 中传递。调用提交接口前先持久记录 unknown/submission_started，再保存接口返回的确切消息编号。提交后按该编号读取当前会话最近一页确认正文和发送方向；确认失败只保留原操作待核查，不用同文猜测编号或重发。

新常规自动发送的适配器请求标记为 purpose=reception，沿用原有按商家、会话、来源消息的防重键。旧操作、账本、回执和失败次数保留；旧快照 unknown 继续走原回执核查，新直接提交的 unknown 走消息编号核查。不会在升级时补发历史失败消息或恢复授权。

显式旧手动确认和原生快照预演接口保留兼容，正常自动发送不触发，也不把它们作为启用前置或失败回退。数据库 schema v2、适配器 Ledger v1 不变，不新增业务 IPC。

## 验证边界

202 项相关定向用例通过，涉及 14 个后端测试文件。为隔离旧测试替身按文件独立进程运行，最终直接发送的 4 个文件另合并复验 48 项通过；重复用例没有再次计数。使用临时数据库和合成原生响应，覆盖凌晨新客户直接提交、没有发送前历史或 Ready/Seal 调用、业务授权回调、防重、撤权、旧回执兼容及未知结果恢复。补充回归证明回执最终写入临时失败时仍保留已返回的消息编号，可沿原操作核查而不重发。发送通道改造阶段，业务检查所在 service.py、continuity.py、context.py、manual_chat.py 与改造前的 0.3.7 构建输入逐字节一致；后续卖家图片规则及 0.3.8 版本号调整另有修改，常规业务检查保留。

源码阶段结果见[验证记录](verification/direct-auto-send.json)，后续打包及最终 EXE 验证见 [0.3.8 候选记录](verification/0.3.8.json)。没有调用真实 AI、发送真实客户消息或修改运行中的商家数据；未执行全量测试，尚未公开发布或替换本机安装。
