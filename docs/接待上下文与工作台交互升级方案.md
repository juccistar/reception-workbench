# 0.3.7 接待与工作台交互升级方案

状态：0.3.7已实现并公开发布，最终EXE隔离窗口、固定更新签名、源码来源及四附件匿名下载核验通过。本文按实现修订，真实图文Accio本轮未进行付费实测，实际范围见[发布说明](0.3.7发布说明.md)。

本版包含六项：图片进入主业务任务、业务补充默认用于自动接待、输入框正文润色、人工建议中文翻译、卖家公司名展示，以及右侧分栏拖拽。

用户已取消“同一客户持续保留上下文”的新增需求。维持现有每次独立发起 Accio 请求、从本地近期消息和当前业务资料组装上下文的方式；本版不新增客户长期记忆、远端会话续接或飞书客户会话路由。现有聊天记录与采购事实继续正常保存和使用。

## 1. 图片进入主业务任务

让主业务 Agent 在同一业务任务中取得相关图片，结合客户文字生成采购需求、中文展示及回复，取消工作台独立生成图片识别报告、再转交文字分析的串行流程。自动接待和手动生成/润色共用图片来源与归属校验。

沿用现有图片下载、原图存储、格式检查、尺寸压缩及商家/客户/消息归属验证。每张图绑定原消息和内容 hash，选取当前相关图片及被引用的历史图片，按预算处理。图片推测的尺寸、材质等信息保留为待确认。

每轮最多四张相关买家原图，受控下载并缓存；初始pixel_access=false，只有本轮确切原生记录证明读取才认为看过。Accio 内部是否另用视觉服务仍由其模型能力决定，因此目标是取消工作台的独立识别任务，不承诺只发生一次模型调用。客户发送继续经工作台业务链路执行。

## 2. 业务补充默认进入自动接待，仅保存当前文本

### 使用方式

当前客户的业务补充默认、无条件加入自动接待、手动生成建议和润色请求，无需新增勾选项、公开标记、使用范围选项或逐条确认。升级后保留的现有最新补充同样默认生效，无需再次确认。

用户修改内容后自动保存，下一轮使用该客户的最新文本；清空输入框即移除该补充。手动触发生成或润色时先保存当前输入。自动接待在生成和提交前核对补充版本，避免继续使用已经被修改的报价、交期或其他条件。保存补充本身不触发主动发送，也不改变人工接管状态或接待授权。

界面说明改为：“用于当前客户的自动接待及回复建议，修改后自动保存。”

### 存储方式

每个商家、每个客户只保留一份当前补充文本。更新覆盖当前值，切换客户及重启后恢复这一份最新内容，不提供历史备注、旧版本列表或回滚功能。

只保留并发校验需要的版本号、内容摘要及更新时间，不为这些版本保存正文副本。同时停止补充修订历史和保存去重记录中的旧正文留存，避免只删除界面历史、数据库仍不断积累旧备注。

升级迁移按客户保留现有最新补充，清理该补充对象的专用历史正文副本；完整业务备份继续遵循现有备份规则。本方案对旧备注的清理不包含其他对象中的客户消息、已提交正文和发送凭据。

### 业务语义

补充属于卖方提供的业务依据，可用于当前客户的报价和履约说明；不改写成买方已确认的采购事实，也不自动晋升为通用政策。与其他资料不一致等语义问题按现行规则进入 warnings。补充改变时，使尚未提交且依赖旧内容的回复失效；已经提交的发送继续按原 operation 核查回执。

## 3. 输入框已有正文时，生成建议用于润色

| 当前状态 | 按钮 | 行为 |
| --- | --- | --- |
| 输入框为空 | 生成回复建议 | 根据客户聊天、图片、当前采购资料和最新业务补充起草回复 |
| 输入框已有正文 | 润色当前回复 | 将当前正文作为待发意图，结合上述资料完善措辞，并按客户语言表达 |

点击时冻结当时的正文及版本，明确标记为未发送内容。润色保留原意、价格、数量、币种、单位及承诺条件；例如“14.5 一件、不含运费”，不能擅自改价格或添加包邮承诺。

结果先进入建议预览，用户采用后放入输入框，再按正常人工流程发送。生成期间可以继续编辑，新结果不自动覆盖后续输入。建议与草稿均不作为已发送聊天记录。

## 4. 自动中文翻译扩展到人工建议

### 翻译范围

| 内容 | 本版处理 |
| --- | --- |
| 买卖双方真实聊天文字 | 继续自动中文翻译 |
| 手动生成的 AI 回复建议 | 生成后自动翻译 |
| 润色当前输入得到的建议 | 生成后自动翻译 |
| 自动接待内部草稿 | 版本核验的发送暂存，不单独翻译或等待采用；发送后按卖家消息翻译 |
| 采购摘要、事实中文展示、事项选择器中文 | 继续由 Accio 在业务生成时直接输出中文 |
| 图片 | 交给主业务 Agent 理解，不送第三方文本翻译服务 |

沿用现有“自动中文翻译”开关、商家翻译启用状态和共享服务配置，无需增加新的翻译开关。开关开启且服务可用时，当前客户的有效人工建议生成后可进入翻译队列；关闭时不产生新的远端翻译请求。

### 展示与发送

人工建议保留原文，在下方展示中文译文。原文与译文相同时不重复显示。翻译过程中显示“正在翻译”，失败时保留原文并支持重试。

采用建议、人工发送和自动发送使用原始回复正文，中文译文仅作展示。翻译异步执行，不阻塞建议预览或原有发送流程。

### 接口与缓存

复用当前第三方翻译服务、独立队列、批量请求、用量统计和持久缓存。将现有翻译来源扩展到人工建议；后台按商家、客户会话、来源对象 ID 和正文版本验证归属，不接受任意界面文本冒充其他客户的来源。

缓存绑定来源类型、正文内容、必要的简短前文及服务配置。展开或收起建议、刷新页面和关闭重开不重复翻译相同来源版本。重新生成或修改正文后使用新版本，旧译文不得覆盖新正文。只对当前有效人工建议按需翻译，stale来源不能新请求，不批量回溯所有历史 AI 输出。

## 5. 黄色框只显示卖家公司名称

左下角黄色区域仅显示卖家公司名称，不显示商家尾号、“当前账号工作区”等附加文字。名称较长时允许换行或省略，悬停可查看完整名称。窗口标题继续展示商家ID。

公司名通过当前授权卖家的只读资料取得并缓存。正在读取或读取失败时显示相应状态，支持重试；后台的身份核验、数据隔离及缓存归属继续使用已核验的 seller_id，账号核验信息保留在设置页。

`refresh_company_profile`为独立慢任务，`get_snapshot`不联网。正常只读 `ai_minisite_get_company_info(dataType=all, language=zh_CN)`，有限读取HTTPS Ali CDN/OSS，缓存仅公司名、seller_id和更新时间；不凭公司名推断 seller_id。

飞书技术回信提供的两个店铺名称为：accio1 对应 Yiwu Yudai Trading Co., Ltd.，accio2 对应 Yiwu Haoxuan Trading Co., Ltd.。程序应动态读取，不硬编码这两个名称。

## 6. 红绿边界可拖拽调整

红色位置增加左右拖拽把手，调整整个右侧栏宽度；最大600，并按窗口可用空间约束宽度，保留聊天区的基本操作空间。

绿色位置增加上下拖拽把手，调整采购需求和业务补充的高度比例，默认0.55。上下两区分别滚动，各自保留最小高度。

拖拽区域提供清晰的悬停提示，支持鼠标拖动和键盘调整，双击恢复默认。宽度与高度比例按商家保存，重启后恢复；窗口缩小时临时约束尺寸，窄屏继续使用抽屉布局。

## 7. 实施顺序与验收

1. 先验证主业务 Agent 读取图片及公司名的受支持通道；无需继续调查远端会话续接。
2. 改造业务补充的当前值存储、自动接待上下文及生成/提交版本校验。
3. 接入当前输入润色，并扩展人工建议的中文翻译来源、展示与缓存。
4. 完成公司名展示、左右和上下拖拽及布局持久化，同步更新实施契约和界面说明。
5. 运行相关定向测试、类型检查、构建及实际窗口验证，再准备候选包。

验收重点：业务补充覆盖更新和清空生效、旧正文不进入备注历史、在途旧回复失效、跨客户不串补充或译文、润色保持原意、中文译文不改变发送正文或阻塞发送、缓存重开可复用、黄色框仅公司名、分栏尺寸重开恢复。图片能力须在明确授权的 Accio 环境验收，Demo 不能代替。

全量测试仅在用户明确指定时运行。100项后端、113项桌面/宿主定向测试、类型检查、构建及源码/最终EXE的隔离窗口验证通过；0.3.7发布和公开附件核验已完成，详见[验证记录](verification/0.3.7.json)。
